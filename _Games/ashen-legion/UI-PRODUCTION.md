## 2. 標準製作順序

1. **確認範圍與現況。** 明列修改哪一頁、保留什麼、哪些玩法不動；讀現行規格、原始檔與最新正式截圖。先檢查既有未提交修改，不覆蓋他人的工作。
2. **先排版，再做正式美術。** 新版面先用線框或獨立預覽確認資訊層級、主要操作和小螢幕配置。方向尚未確認，不直接大批替換正式素材。已確認方向內的修錯，不反覆要求使用者重新選風格。
3. **辨識並拆出元件。** 列出視窗、商人欄、卡片、圖示槽、名稱、摘要、數值列、按鈕、詳情窗。每個元件都要有內容區、裝飾區、命中區及狀態。
4. **製作母元件與變體。** 先統一視窗、卡片、主／次按鈕，再衍生稀有度與狀態。沿用同一組參考圖、材質、光源與線條，不逐張任意換風格。
5. **接入共用組裝規則。** 使用既有九宮格、文字量測、商品模板與動畫分組。正式文案、長名稱、真實價格從這一步就要加入，不只用短 placeholder 驗證。
6. **接正式規則與輸入。** 顯示、購買、停用、重骰、鍵盤及觸控共用正式 action。確認失敗時不會扣錢、換商品或留下假成功狀態。
7. **完整建置與批次驗收。** 同一輪涵蓋桌面、中尺寸、小橫版及操作狀態；把找到的問題一次修正，再做確認。不要無止境微調無關細節，也不要帶著已知阻斷問題交付。
8. **對照設計稿並交付。** 在相同尺寸／狀態比較原核准排版與正式成果，提供可試玩的版本、報告和未驗證項目。預覽成功不等於遊戲實作成功。

## 3. 美術與素材規範

- 現行方向以榛姨與核准的精細商店素材為準；新元件遵循 [DESIGN.md](DESIGN.md)。不能因參考另一款遊戲，就把整套畫風換掉。
- Hades 等外部截圖只研究資訊層級、選取與卡片表現；保存來源與用途，不把第三方截圖、角色或裝飾直接打包成遊戲資產。參考索引在 [references](design-v1/references/README.md)。
- 生成圖是素材或示意圖，不能把整張 UI 截圖當成正式可操作畫面。
- 文字、價格、圖示數值與狀態由程式疊加；不要烙死在生成圖片裡。
- 圖片需檢查透明邊緣、裁切、留白、壓縮後可讀性，以及與母元件的色調／線條一致性。保留原稿，不覆蓋唯一來源。
- 角色和裝備圖片等比顯示。視窗／卡片／按鈕使用九宮格；切線根據來源像素與裝飾位置決定，四角保持比例，只延展可延展部分。
- 「Atlas」是素材區域管理，不會自動解決排版；目前使用獨立九宮格切片，不為換名詞新增另一套 renderer。

## 4. 版面、文案與資訊層級

- 先分清背景、主視窗、內容欄、操作列、詳情窗。視窗不要因內容塞不下就任意改滿版。
- 同列元件由同一模板產生，卡片等高、按鈕同高、數值對齊；不能靠每張卡各自微調補丁維持外觀。
- `100×100` 是正規化座標，不是 `100×100 px`。字級、手指命中尺寸須在實際畫布像素重新量測。
- 新介面沿用已確認的可讀性基準：以 1920×1080 設計像素量測，輔助文字至少 14px、主要名稱／價格／操作至少 16px；主要互動區至少 44×44px。這是專案目標，不宣稱它直接等同完整無障礙認證。
- 空間不足的處理順序：重排 → 減少重複資訊／裝飾 → 長敘述移至詳情 → 必要時設計可驗證的捲動。不靠縮成小字、裁掉字形或壓扁按鈕過關。
- 商品卡保留一句核心效果＋成本，整體縮放也不能省略；用完整商品庫驗證兩行以內且沒有省略號。完整條件、效果與交易成本不能在詳情中消失。名稱被縮略時需另有完整名稱入口。
- 金幣、結晶、價格等穩定概念優先用既有圖示＋數字；不明確的圖示要有說明與讀屏名稱，不能只靠顏色傳達意思。
- 文案必須反映實際行為。「買入」不等於「買入並裝備」，「重骰費用」不是「剩餘次數」。
- 商店專屬規則：左商人、右側四卡水平排列、稀有度用底板色、點卡開詳情。不要把「所有介面都四張卡」當成全遊戲通則。

## 5. 互動、動畫與無障礙

- 顯示為可點的完整元件都應能點；卡片圖片不能擋住卡片 action，按鈕裝飾不能吃掉點擊。
- 正常、hover、按下、鍵盤焦點、不可購買、已購買、空內容、載入與失敗狀態要逐項確認；不適用的狀態註明原因。
- 視覺停用與邏輯停用一致；不能只把文字變灰，卻保留可觸發的透明按鈕。
- 詳情開啟時，下層商品與重骰不能被誤點；關閉後返回正確的商品焦點，而不是上一次開啟的商品。
- Tab 可到達操作項、Enter／Space 確認、Escape 關閉詳情；焦點必須看得見。Space 不可穿透成派兵。
- 純畫布介面也需要語意控制；目前商店採 Canvas fallback 按鈕投影，同一份 action、同一份狀態，不另做一套交易規則。
- 動畫以整個元件為單位；底板、圖示、文字、數字與命中區一起移動。價格、條件等重要文字不等待打字動畫。
- 開場動畫不阻塞操作，遮罩／視窗底材不套商品 hover 縮放；要有 reduced-motion 路徑，pointercancel／失焦時清除按壓狀態。
- 語意標籤存在不等於讀屏通過；檢查瀏覽器實際 accessibility tree。模擬視窗不等於實體觸控測試。

## 6. 程式與來源責任

| 層次 | 負責內容 | 不應做的事 |
| --- | --- | --- |
| `main.luau` | 價格、資源、購買、重骰次數／費用、裝備效果 | 把單款遊戲玩法移進引擎 |
| `ui/formal-ui.luau` | 頁面、文字、語意 action、原生 UI 節點組裝 | 只改合入 `main.luau` 的生成區，忘了來源 |
| `presentation/ui-components.mjs`、`ui-skin-data.mjs` | 共用切片、來源尺寸、字寬量測 | 每顆按鈕重寫一套伸縮法 |
| `presentation/adaptive-ui.mjs`、`ui-motion.mjs` | 固定桌面組版與同組動畫 | 另算價格、改商品或 RNG |
| `presentation/shop-accessibility.mjs`、`host.mjs` | 焦點、語意與正式 action 輸入 | 複製購買規則或做第二套畫面 |
| 官方 Unone renderer／input | 通用繪圖、命中及輸入能力 | 因單一頁面需求偷塞遊戲規則 |
| `dist/web` | 匯出成品 | 當成唯一手改來源 |

新增引擎能力前先判斷是玩法還是可重用能力，遵循上層 AGENTS.md。修正應落在擁有該責任的最小共用位置，不引入不必要的框架。保留既有未提交修改；版本提交依使用者要求，不把整理文件當成自動發布授權。

## 7. 驗收門檻

### 幾何與文字

- [ ] 主視窗在畫布內，卡片在視窗內，內容在各自安全區內；完全落在父框外也要報錯。
- [ ] 同層文字、不同卡片、不同操作的 AABB 不重疊；背景／底板與自身內容的刻意重疊列明例外。
- [ ] 同 action 的文字帶與上下命中帶合併檢查；擴大 hit 區不可壓到相鄰 action。
- [ ] 卡片等高、按鈕同高、間距一致、九宮格四角沒有拉扯。
- [ ] 用正式 Canvas 實際字形量測 clipping 和字級；長中文、數字、百分比與長名稱都檢查，不能只算字數。
- [ ] 開場、hover／press 和詳情開啟狀態也檢查，不只看靜止第一幀。

### 真實操作與規則

- [ ] 走正式入口完成查看、購買、返回、重骰、餘額不足；實際扣款與顯示一致。
- [ ] 金幣／結晶不能互相代扣，失敗不變更商品或成功計數；新造訪與普通切頁不能混淆。
- [ ] 測鍵盤、滑鼠及合成觸控；焦點、遮罩、停用、返回與輸入釋放一致。
- [ ] 沒有載圖失敗、瀏覽器例外或新增遊戲回歸。

### 目視與範圍

- [ ] 把正式版與核准稿並排比較：構圖、比例、榛姨位置、水平卡列、文字層級、材質、留白及詳情窗。
- [ ] 每個差異註明：整體等比縮放、已確認變更，或待修問題；不拿「測試綠燈」掩蓋偏離設計稿。
- [ ] 報告標示版本、尺寸、操作方法、結果與證據路徑。測試 fixture、真實遊玩和設計預覽分開。
- [ ] 未測項明列。不能把 Web 測試說成 native、把合成觸控說成實體手機、把語意樹說成完整 NVDA／VoiceOver 認證。

## 8. 現行建置與測試入口

以下命令在遊戲目錄執行，每一步成功才進下一步。只改文件不必重建遊戲；更動素材切線才需重跑切圖。

```powershell
# 僅素材切線有變時
node tools/slice-shop-assets.mjs

# UI 或遊戲來源有變時
node tools/build-formal-ui.mjs
node tools/finish_export.mjs

# 裝備店驗收
node tools/verify-shop-components.cjs
node tools/verify-shop-accessibility.cjs
node tools/verify-currencies.mjs
node tools/verify-formal-ui.cjs

# 所有正式畫面／狀態 + 真實操作（2026-09-19 補）
node tools/verify-desktop-ui.cjs
node tools/verify-all-screens.mjs
node tools/verify-all-ui-interactions.cjs
node tools/verify-quick-deploy.mjs

# 角色肖像更換後：來源映射、匯出一致性、透明度、邊界及原稿
node tools/verify-character-art.mjs

# 地圖更換後：原稿／正式／匯出雜湊、七段路線與 Luau 站點一致
node tools/verify-map-art.mjs
```

瀏覽器測試需已啟動正式預覽（目前 `http://127.0.0.1:8190/`；可用測試的 `GAME_TEST_URL` 指定）。唯一版面為 1920×1080；1920×1080、1280×720、1600×1000、2560×1440 是整體縮放／留黑邊的視窗測試，不是四套排版。不得隨視窗改卡列、字級、斷點或旋轉。載入畫面、世界、UI、焦點及輸入共用 stage 轉換；`node tools/verify-desktop-ui.cjs` 比較相同節點矩形／字串並點擊留黑邊後的真實畫布。新增頁面需補該頁測試，商店腳本不會自動覆蓋它。

## 9. 交付格式與維護

交付只需說清楚：**改了什麼、哪裡可試、實際通過什麼、還沒測什麼。** 保留可開啟的成果／報告路徑，不只回覆「完成」。

- 新美術方向更新 `DESIGN.md`；商店尺寸更新商店詳細規格；玩法更新經濟規格與 Luau；驗證結果寫報告。一次變更不要留下相互矛盾的多份新數值。
- 舊草稿和測試保留追溯，但入口加歷史標記與現行文件連結，不用舊圖冒充新版成果。
- Impeccable 等 skill 可用來補充檢查維度，不是美術裁判或 Canvas 驗收器。沒有 warning 不等於合格；誤判需附具體排除理由。
- 發現失敗時先分類為美術、排版、命中、語意或玩法問題，再修擁有該責任的來源；不得用降低字級門檻、跳過測試或硬改測試數值讓結果變綠。
