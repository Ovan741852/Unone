## UX 審核結論

美術已有辨識度：榛姨、店主肖像與森林綠金框材屬於同一個世界。但資訊安排還沒跟上，最大的問題是：**比較必要的效果藏太深，不重要的資訊卻一直出現。**

兩位審查者獨立檢查來源、正式截圖及各自的新瀏覽器分頁；A 完成前，沒有讓偵測器結果影響 A 的判斷。以下是改版前全遊戲基準評分，不因單獨修好地圖就提高全遊戲分數。

| 準則 | 分數／4 | 主要判斷 |
|---|---:|---|
| 狀態可見 | 3 | 部分限制、剩餘次數不明 |
| 使用者語言 | 2 | 科技內部代號、機率語意難懂 |
| 控制與返回 | 3 | 取消機制有基礎，焦點返回不完全一致 |
| 一致性 | 2 | 商店確認方式與資訊層級不一 |
| 錯誤預防 | 2 | 有確認窗，但交易資訊不足 |
| 辨識優於記憶 | 2 | 裝備、研究、附魔難以並列比較 |
| 操作效率 | 2 | 逐窗查看、配裝中轉過多 |
| 精簡與美感 | 2 | 美術完整，無關資訊仍常駐 |
| 錯誤復原 | 2 | 「無法購買」未說清原因 |
| 說明與引導 | 2 | 核心指南到戰鬥暫停才出現 |
| **合計** | **22／40** | **基礎可用，資訊與流程需要改善** |

### 五項優先問題

1. **P1｜交易前說不清楚會得到什麼。** 契約只寫「一層強化」；科技顯示內部代號，短畫面還把 `0.35` 拆行；符文需明確區分總中獎率與成功開獎後的獎級分配。這會讓玩家做錯決策。第一層應有「對象、核心收益／代價、成本」，詳情再補觸發、期間、限制及不能購買原因。工具方向：`impeccable clarify`。[契約來源](D:/Projects/YesSir/_Games/ashen-legion/ui/formal-ui.luau:663)、[科技卡片](D:/Projects/YesSir/_Games/ashen-legion/ui/formal-ui.luau:738)。

2. **P1｜精簡過頭，變成靠記憶比較。** 研究價格與效果逐窗查看；短橫版裝備缺核心效果；附魔沒有並排新舊詞綴。應保留一句效果摘要，並列目前／候選裝備和派兵費差額；完整條件才放第二層。工具方向：`impeccable layout`。[研究入口](D:/Projects/YesSir/_Games/ashen-legion/ui/formal-ui.luau:519)、[附魔結果](D:/Projects/YesSir/_Games/ashen-legion/ui/formal-ui.luau:655)。

3. **P1｜同名按鈕缺少操作對象。** 即時語意樹確認兩個「切換」、兩個「建立新檔」，沒有設定名稱／存檔欄位。依賴讀屏的人難以辨認。應改成「切換語系，目前繁中」「在札記二建立新檔」，沿用既有語意投影即可。工具方向：`impeccable harden`。[來源](D:/Projects/YesSir/_Games/ashen-legion/presentation/shop-accessibility.mjs:69)。

4. **P2｜新手入口不直覺，熟手流程又太長。** 新建遊戲藏在「讀取進度」，指南太晚出現；一般商店離開仍經配裝。建議依存檔狀態顯示建立／繼續領地，出戰前提供可略過的短說明，並考慮直接出戰入口；高影響交易保留確認。工具方向：`impeccable onboard`。[入口](D:/Projects/YesSir/_Games/ashen-legion/ui/formal-ui.luau:416)。

5. **P2｜不屬於當下任務的資訊沒有退場。** 設定／存檔仍顯示局內貨幣，AUTO 未啟用仍顯示目標設定，結算重複餘額與敘事。應讓第一層只回答「現在能做什麼、會花多少、得到什麼」；進階 AUTO、累計戰報及長故事進第二層。工具方向：`impeccable distill`。[AUTO 入口](D:/Projects/YesSir/_Games/ashen-legion/ui/formal-ui.luau:371)。

### 已完成的地圖修正

舊三角樹林與粗路線已換成精細森林地圖。本站、抵達狀態、下一步集中在右側；地圖不再重複章節台詞或貨幣，讀屏也改報抵達狀態。七站維持線性遠征，不做假的選路按鈕。

全頁 **296 組版面檢查通過**，含地圖 112 組；另實際測了出征、自動抵達、進出地圖與景點不重抽。這不等於自然玩完七關，也不等於全遊戲 UX 通過。[地圖成果與證據](D:/Projects/YesSir/_Games/ashen-legion/tests/map-layout/REPORT.md)。

### 值得保留與認知負荷

保留三點：角色／材質有個性；危險操作有取消防護；短橫版重排與可見鍵盤焦點已有基礎。

八項認知負荷檢查都有局部問題：單一焦點被 AUTO 分散；研究／AUTO 選項分塊不足；附魔新舊關聯分離；舊地圖主次顛倒；附魔前後階段同時可見；AUTO 選項過多；裝備比較依賴記憶；核心效果與次要台詞的揭露層級相反。五個裝備部位本身符合心智模型，不必為減少選項硬拆頁。

情緒旅程推估是「期待冒險 → 研究與比較停頓 → 商人帶來溫度 → 戰鬥規則疑惑 → 結算學習回饋不足」，並非玩家研究結果。

### 不同玩家的風險

- 新手：以為沒有存檔就不能開始，不知道破防與開獎的關係。
- 熟手：逐窗比較與固定配裝中轉拖慢重複遠征。
- 讀屏／鍵盤玩家：同名控制缺對象，部分關閉操作不回到原入口；已有焦點框不代表完整讀屏通過。

次要問題：語系設定可選 English，但來源未見相應 UI 翻譯，屬來源推論、未實際切換；藥水圖示辨識度低；已穿戴物品應明示「已穿戴」；累計金幣前的大「＋」容易被當成本關新獎勵。

### 自動檢查的界線

偵測器有 2 個警告、4 個建議：字型解析與載入動畫是情境誤判，4 個色票屬文件涵蓋不足，不能拿來推翻既有美術。版面掃描 0 項也不代表 Canvas 介面合格。瀏覽器工具不支援安全注入，沒有顯示檢查覆蓋層，改用正式渲染、字形／AABB 與操作證據。語意與焦點檢查參照 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)。

未驗證 native、Safari、實體觸控、200% 縮放、完整讀屏與整場通關。其餘五項優先問題目前是審核結果，沒有冒稱已修好。
