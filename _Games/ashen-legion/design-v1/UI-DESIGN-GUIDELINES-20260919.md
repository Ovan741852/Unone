# 正式 UI 設計準則

定位：現行**裝備店詳細規格**。通用製作流程與交付門檻見 [UI-PRODUCTION.md](../UI-PRODUCTION.md)，跨元件視覺語言見 [DESIGN.md](../DESIGN.md)。本頁尺寸不可直接套成所有遊戲頁面的固定模板。

這份準則是 `ashen-legion` 正式 Unone Canvas UI 的共同基準。座標不是像素，而是 100 × 100 的 normalized design space；`formal-ui.luau` 最後再由 host 映射到實際畫布。

## 1. 版面與安全邊界

- 所有節點必須落在 `0..100`；主要視窗保留至少 4 units 的外框安全邊界。
- 視窗內容的標題列預留 5 units，底部操作列預留 7–8 units；正文不要貼住視窗邊緣。
- 2026-09-19 使用者修訂：固定 1920×1080 電腦版構圖，不做自適應排版或旋轉；視窗只等比縮放完整 stage 並置中留黑邊。所有字級、元件尺寸及命中底線均為設計像素，非縮放後 CSS 像素。卡面保留一句核心效果＋成本，詳情提供完整規則。
- 2026-09-20 使用者修訂：所有返回／關閉入口固定在視窗右上角，使用 `icon-close` 叉叉與至少 44×44 設計像素命中區；底部不再放返回文字按鈕，保留購買、穿戴、出戰與確認等正向操作。刪除／保留等不可逆或確認流程可保留明確文字取消。
- 視覺背景可以滿版，但互動元件不能用背景作為命中區域。

## 2. 間距 token

| Token | Units | 用途 |
| --- | ---: | --- |
| `s1` | 1 | 同一組內的最小卡片／欄間距 |
| `s2` | 2 | 圖示與文字、文字與數值 |
| `s3` | 3 | 同一資訊區塊之間 |
| `s4` | 4 | 區塊與區塊、標題與正文 |
| `s6` | 6 | 視窗內側留白、主要分段 |
| `s8` | 8 | 視窗底部操作區與內容區 |

實作規則：

- 同列卡片使用一致寬度與一致 gap；不得讓最後一張卡貼到視窗邊緣。
- 裝備店視窗為 `(6,6,88,88)`。一般橫版四張卡使用 `14.75w / 51h / 1.0 gap`，整列由 `x=28,y=29` 開始，最後一張右界為 `90`，不能超出視窗的右界 `94`。商人欄為 `x=10..26`。沒有短視窗例外，縮放時各元件相對位置不變。
- 卡片內容必須被自己的底板包住；卡片與下一列操作區至少留 1 unit 的垂直空間。
- 文字不可跨越相鄰卡片；需要換行時先縮短文案或增加卡片高度，不用負 margin 疊字。

## 3. 資訊層級

- 卡片只放：裝備圖、名稱、一句核心效果、價格、派兵費變化、詳情提示。整張卡開啟同一詳情，不再加一個重複框住的小按鈕。
- 稀有度用底板色表達；不要再增加一排會和說明重複的 badge。
- 完整故事、發動條件、效果與購買行為放進詳情視窗。
- 購買只顯示真實語意：商店按鈕是「買入」，買入後到部隊配置穿戴；不能寫成「買入並裝備」。
- 一個部位最多一件裝備，介面不顯示疊加數量，也不提供會造成誤解的 stack counter。
- 商店底部並列「部隊配置」與「直接出戰」；前者保留完整配裝流程，後者使用目前配置。新購裝備不會自動穿上；附魔待選及詳情開啟時，出戰不得繞過決策。
- 裝備店的金幣／結晶餘額、商品售價與重骰費用使用既有精細圖示＋數字，不重複顯示屬性名稱。重骰為環形箭頭＋水晶＋費用；名稱與用途保留在 hover 說明及畫布替代描述。派兵費變化等容易混淆的概念仍保留說明。
- 圖示與數字必須同組動畫、分開安全區；重骰的圖示與數字不可擋住原本按鈕命中區，停用時不得留下可點的透明覆蓋。
- 重骰不限次數，顯示下一次消耗 2、4、6、8…結晶，實際金額只取自 Luau 的 `refreshCost`，不得在瀏覽器重算另一套價格；下一次造訪重設，詳見 `tests/CURRENCY-SPLIT.md`。

## 4. AABB／命中區域規則

以 `tools/verify-shop-components.cjs` 的正式 Web player 驗收為主。`tools/verify-shop-layout.mjs` 是需 native CLI 的附加檢查，不能用只看 normalized 節點的結果取代實際字形驗收。

- 背景、視窗底板、卡片底板與自己的文字／圖示重疊是「有意的父子層級」，必須明確列入 allowlist。
- 不同卡片、不同操作按鈕、不同文字區塊不得有正面 AABB 重疊；邊界相接不算重疊。
- 按鈕的上下延伸命中區只能服務同一個 action，不能跨到相鄰按鈕。
- 整張商品卡（含圖片）必須命中同一個詳情 action；卡片透明命中層位於卡片內容之上、modal 遮罩之下，並與整張卡一起動畫。
- 商店商品列、頁籤、底部操作及詳情按鈕以至少 44×44 設計像素 驗收；同 action 的文字／上下命中帶先合併計算。這是專案易用性目標，不冒稱 WCAG AA 的通用最低要求。
- modal scrim 可以覆蓋背景，但必須位於詳情視窗之下；詳情視窗內的關閉／買入／取消按鈕彼此不能重疊。
- 每個互動節點都要檢查 bounds、命中區域與同層 sibling overlap，不只檢查肉眼看到的文字。
- 卡片必須完整包含在視窗內，內容也必須完整包含在卡片安全區內；完全落在父框外也必須報錯，不能只檢查相交的項目。
- 測試截取正式 Canvas 的每次 `fillText`，用實際字形邊界驗證 clipping。裝飾與字框分開；不能靠裁掉字形來通過。

## 5. 共用元件／Atlas 契約

- `presentation/ui-components.mjs` 是共用切片與文字規則，`ui-skin-data.mjs` 是切圖器生成的來源尺寸；`ui/formal-ui.luau` 的 `nineSlice`／`button`／單一商品模板負責組裝原生 image、text、button 節點。
- Atlas 是來源區域管理，不會自動排版。2026-09-20 起使用 Core `image.slice` 的單圖單節點；既有裁切／邊距 metadata 不变，不再要求九張 PNG。官方 Web/native host 負責真正九宮格绘製，不能用整張拉伸替代。
- 視窗按設計像素等比縮放邊框；商品卡保留完整上方徽章比例，只延展中段；按鈕按統一高度計算角落比例，只沿寬度延展中段。禁止用目標寬高的 16% 同時當四角尺寸。
- 按鈕來源先去除透明留白，商店商品列與詳情按鈕高度統一為 `6.5 units`（70.2 設計像素）。長寬可依用途不同，但同列高度、四角比例、字級和文字安全區一致。
- 按鈕字形避開左右固定角；完整底板都可點，文字帶與上下 hit 區使用同一 action。
- 一般卡片內容左／右約 `1.75`，上方徽章保留 `8.5`；固定桌面配置圖片／名稱／核心效果／費用／詳情提示。名稱最多一行可省略；核心效果必須在兩行完整顯示，改寫摘要不能改變技能意思。派兵費固定使用金幣圖示＋變化量。詳情保留完整效果。
- 次要操作、研究、裝備槽與 AUTO 選項使用 `control-quiet-v3`：原稿去透明邊後 1940×412，四邊切線各 80px。細舊金邊依設計像素等比，禁止挪用厚葉飾按鈕的切線。主操作、稀有度卡片及視窗保留精細裝飾作為視覺重點。
- 現行商店正文 22px、商品名／價格 28px、操作 24px；自動縮字驗收底線為輔助 20px、主要 24px（設計像素）；不能降低門檻來讓爆框測試過關。缺空間先重排或漸進揭露。測試以正式 Canvas 的實際字形尺寸為準。
- 字寬以實際 Canvas `measureText` 測量，字型必須與正式 renderer 相同。英文／數值如 `12`、`30%` 不拆成零碎行。
- 卡片框、圖片、說明、數值和按鈕為同一動畫組。遮罩和視窗底材不套 hover/press 放大。
- 視窗使用安靜的不透明深綠底材，外圍保留模糊遊戲背景；不要把小塊紋理整張放大。
- 部隊裝備使用左側穩定配裝區＋右側 Drawer：點擊部位才開啟裝備列表，Drawer 內採三欄 Grid；關閉 Drawer 不離開配裝主畫面。Drawer 的卡片保留圖示、名稱、一句效果、派兵成本與詳情／穿上 action。
- 官方參考：[Unity 9-slicing](https://docs.unity.com/en-us/engine/6000.3/manual/unity2d/sprite/9-slice)、[Godot StyleBoxTexture](https://docs.godotengine.org/en/stable/classes/class_styleboxtexture.html)。區分 texture margin 與 content margin。

## 6. 交付前 checklist

1. 更動素材切線時先執行 `node tools/slice-shop-assets.mjs`。
2. `node tools/build-formal-ui.mjs`；成功後才執行 `node tools/finish_export.mjs`，任一步失敗不可繼續交付。
3. `node tools/verify-shop-components.cjs`：四種桌面視窗的同一固定構圖 × 商品列／四件詳情、購買／回執、六個進場時間點和長文案；報告為 `tests/shop-layout/components-report.json`。
4. `node tools/verify-shop-accessibility.cjs`：Edge 真實鍵盤與合成觸控、商品圖點擊、Tab、Enter／Space、modal 焦點限制、Escape 返回、停用購買與重骰、桌面留黑邊時的焦點；用瀏覽器原生 accessibility tree 驗證語意。`node tools/verify-currencies.mjs` 驗證實際 Luau 遞增費用、無次數上限、資源不足與造訪重設。
5. `node tools/verify-formal-ui.cjs`：真實滑鼠購買、換裝、出戰回歸。若 native CLI 存在，另跑 `verify-shop-layout.mjs`；全局歷史 findings 與本次變更分開記錄。
6. 目視 `components-1920.png`、`components-1600.png` 及詳情截圖，與已確認的 v4 視窗排版對照；AABB 通過不代表美術驗收自動通過。

## 7. 商店鍵盤／語意投影

- `presentation/shop-accessibility.mjs` 把同一份正式 Canvas UI action 投影成 HTML canvas fallback 按鈕。它只負責語意、焦點和輸入，不繪製另一套介面，也不自行判斷購買價格與遊戲結果。
- 金額、物品名、派兵費與完整技能提供讀屏文字。Tab 逐項操作，Enter／Space 確認；詳情內限制焦點，Escape 關閉並返回實際開啟的卡片。
- 鍵盤使用可見金色焦點框，矩形取自正在渲染的同一 tree；滑鼠／觸控不留下多餘焦點外框。停用 action 不可啟動，Space 不得穿透為派兵。
- 此規範本次驗證範圍為 Web 裝備店與詳情，不宣稱全遊戲、native、所有瀏覽器或實體讀屏軟體已完全通過。
