# 雙人互動：共同事件，不是單人改數值

2026-09-19；主代理規劃／驗收，Luna 實作。待測試與使用者確認重開後才套用目前直播。

## 查到的現況

- `help` 在醫館直接讓自己購藥回血，沒有醫者。`use_medicine` 才應是單人的隨身藥材自療。
- `propose` 靠長期殘留的 `proposedTo` 判定互相求婚，沒有同一場互動的明確接受／拒絕。
- 比武有雙人交替攻擊，但採演武場自動湊對，缺少指定對手的邀請與回應。
- 偷竊在六單位距離內立即成功轉走最多 18 文，没有接近、嘗試時間與失敗；沒有獨立搶劫行為。
- 一般人際行為停在原地，除了攻擊之外不會追近選中的對象。

## 原則

這是 Luau 遊戲規則，不是 Unone 引擎原語。NanoJev 選發起、對象、回應，以及 after_current／interrupt_now；Luau 只驗是否合法、能否接近、實際耗時、資源與後果。不得代替對方同意、拒絕、反擊、逃跑，也不得因人格或關係分數強制選擇。

雙人不等於必須雙方同意犯罪：偷竊／搶劫有受害者，但不能要求受害者自願才能發生。未察覺的偷竊不可把全知觀察者的資料洩露給受害者模型。知道發生什麼以後才有自己的反應選項。

## 最小共同契約

- 每場唯一 id、類型、發起方與對方、各自角色、階段、時限、兩份實際決策來源、完成或失敗原因。
- 一人最多一場配對；不得自指、搶占忙碌角色、接死人、覆寫另一場。
- 接近 → 通知／等待回應 → 雙方就位 → 持續執行 → 結果。犯罪不經同意閘門，但仍有真實的對象、距離、時間和結果。
- 原地等待邀請不自動停止對方原本工作；已同意並執行時不能同時工作領薪。發起者也不能一邊配對一邊結算原工作。
- 中途離開／改主意／死亡／超時都釋放配對，不永久卡住預定行動，不偷偷替角色選下一個意圖。
- 回應綁定原配對 id 及對象；舊 request 和已排定但過期的 accept 不能同意下一個人的邀請。普通預定行動仍保留。
- 既有格子尋路、占格和安全換格沿用，不瞬移、不重疊、不將對方拖來。接近與結算均要求安全格點和近距離。
- 金錢只走 Economy.transfer；藥材有真實庫存／隨身來源，先驗雙方與條件，再一次結算，死亡遺產不自動搶走。

## 各行為

| 行為 | 雙方角色 | 完成條件與後果 |
| --- | --- | --- |
| 求醫／治療 | 醫者、傷者 | 指定對象、同意、同地執行。醫館職員在醫館可提供付費療程；或施治者消耗隨身一份藥材作現場救治。沒有醫者／藥／錢不能假回血。 |
| 求婚 | 求婚者、被求婚者 | 同一場邀請內明確接受、双方在場且未婚才結婚。拒絕／逾時不成婚。 |
| 決鬥／切磋 | 挑戰者、應戰者 | 指定對手並接受，才进入既有非致命交替交鋒。未接受不開打。 |
| 偷竊 | 行竊者、被竊者 | 接近、持續嘗試、規則隨機成功／失敗／察覺；被竊者不被強制停下，不同意也可能被竊。 |
| 搶劫 | 搶劫者、被威脅者 | 公開威脅與有限反應時間；屈服、反抗、離開由被威脅者自己的 NanoJev 決定。無回應不冒充同意；搶奪仍須近距離且可能失敗。反抗沿用真實戰鬥，沒有自動反擊。 |

交談、合作、示好一併接入邀請／回應與共同結算。沿用既有關係／人格反應數值，改變的是雙方參與的條件；不增加另一套人物決策。

## 玩家／模型可見資訊

- 頭上：對方名字＋自己的互動角色／階段。
- 詳情：目前自己的意圖與「正在收到／參與的互動」分開；顯示對象、是否等待回應、完成／拒絕／失敗原因。
- Debug：兩端同一 pair id，發起與回應的 request id 分開。資料是事件／決策證據，不是模型思維鏈。
- 模型只得到自己知道的互動；緊湊文字、最多四位候選人物、實際 tokenizer 1024 上限。不能靠截斷換取通過，也不載入第二個模型。
- 候選人物補充實際傷勢與治療來源位置，否則模型無從選擇需要治療的患者。互動結束後保留一筆已知對象／結果的精簡記憶；未察覺的偷竊不透露行竊者。
- UI 保留現有版型／標籤固定錨點；依 impeccable clarify 使用簡短且區分主動／被動的狀態文字，JS 不計算結果。

## 驗收

1. 生產 Luau 雙人生命週期與來源驗證：成功、拒絕、未回應、取消、遠離、死亡、過時回覆、忙碌第三人。
2. 治療資源不足無副作用；完整療程只扣一次錢／藥／加一次血；求婚不能單方結婚；拒絕決鬥不傷害。
3. 偷竊／搶劫失敗不扣錢、重複 tick 不重複轉帳，受害者不被腳本代選反應；未察覺時模型無偷竊者身分。
4. 雙方角色／對象／階段一致，標籤與詳情對應；原有姓名、墓誌、鏡頭、建築等回歸保留。
5. 40 人人格與配對雙角色、長進度／反應、四鄰人輸入壓力測試 <=1024；語法／型別／引擎 deterministic checks 通過。
6. 合成輸入僅驗規則，不宣稱 NanoJev 真模型品質改善。舊世界 receipt 不當作新雙人流程實測。

## 審查特別追查

- 真正從住宅走到醫館的端到端流程；不能靠測試直接改 location 掩蓋抵達地點仍是原住宅的錯誤。
- 犯罪的「拒絕」不提供魔法免疫。「離開」要實際產生位移／距離；被格子堵住仍近距離時不能宣稱已逃脫。
- 時限容納四十人的非同步推論排隊，不在兩秒內沒收到模型答覆就代選拒絕／同意；120 幀仍只是錯開提交資格。
- 依配對 id 固定結算順序；接近移動對象時只在格子改變或路線失效時重算，不每幀重跑所有路徑。
- 新的非身體原因失敗也會使用 task.failed，UI 不能一律宣稱「因體況失敗」。

沒有本次重開同意前，不重啟 live native/model、不改 OBS 來源、不重啟推流。
