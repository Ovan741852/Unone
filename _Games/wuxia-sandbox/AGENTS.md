# Wuxia town: ownership and truthful model evidence

- The user explicitly requires **all character intentions to be chosen by NanoJev**, not utility scores, scripted poverty fixes, or automatic social/crime/marriage triggers. Do not silently restore a heuristic fallback.
- Lookahead-v2 also requires NanoJev's timing choice: `after_current` versus `interrupt_now`. One queued next plan may be revised while the current unit executes; 120-frame eligibility is independent of completion. Luau defines finite execution units and safe cell-boundary handoff, never chooses the next intention/timing. Clear old-context requests on handoff. Acknowledgement (`planning_request_id`) is distinct from start (`decision_request_id`). Keep source-matched active and future receipts separate. Death/reset clears plans. Run `tools/check-lookahead.py` for synthetic execution tests. Historical pre-v2 tapes are not valid v2 timing evidence.
- Luau owns economic rules, observations/candidate descriptions, requests, transport validation, navigation, collision, damage and relationship effects. Python loads the real checkpoint and returns its probability-based choices; it must not simulate the town. JS is presentation/camera only.
- Action-duration rules are Luau-owned: sample once per started unit; arrival/reservation/paired occupancy determine actual execution time. Meals, item use and purchases settle only after their positive duration, once. Productive effort advances with game minutes and condition, not tick count; preserve eight-effort wages and partial work. Rest recovery is gradual and can continue at home after the unit completes until NanoJev changes intent. Pair performing time is shared and game-speed-scaled; the 90-second model-response window is not speed-scaled. Pause freezes both. Combat ends through actual strikes/results, not a fabricated duration. Run `tools/check-action-durations.py --tokens` with the isolated tokenizer Python plus lookahead/paired/life/economy/realism checks. All living residents with remaining native routes have viewer lines independently of selection; run `node tools/check-routes.mjs`. No route/AI decisions belong in JS.
- Paired interactions in Luau share one session id and explicit initiator/recipient roles. Treatment, proposal, sparring, conversation, cooperation and flirting require the counterpart's NanoJev acceptance before joint effects; personal `use_medicine` remains single-person. Never revert `help` to unattended clinic healing or `duel` to arbitrary automatic matchmaking. Response requests/queued plans bind the exact pair id, phase and counterpart; stale or wrong-target responses cannot accept another invitation. Theft/robbery do not require victim consent, but require real proximity/time/results; hidden theft must not leak to the victim's model. Resistance/leave/yield are victim model choices, not scripted reactions; choosing leave alone is not proof of escape. Money/items settle once and estates stay preserved. Run `tools/check-paired-interactions.py --tokens` with isolated NanoJev Python (tokenizer only); synthetic fixtures are execution evidence, never live model-quality evidence.
- Before model readiness, residents wait. Later, a pending request may retain the last approved action. Use bounded one-request-per-resident, oldest-first scheduling. The 120-frame cadence is submission eligibility, not a claim of GPU response latency.
- `tools/nanojev-agent.py` defaults to full-distribution T=1 sampling, with actual probabilities and checkpoint SHA in `.runtime/nanojev-status.json`. UI evidence is matched to Luau's `decision_request_id`; do not invent a rationale or call it model chain-of-thought.
- Root NanoJev checkpoint is navigation-trained, not town-trained. Model integration verification does not establish believable economics/personality quality. Surface this limitation.
- All money moves through `Economy.transfer`. Include estates in conservation; keep inventory accounting intact. Never cap wealth at 100.
- `Life` in main.luau owns fatigue/rest/sleep, mood summaries and world time. Never force a new intention at night; `rest` remains NanoJev's choice. Recovery starts only at the residence, not on the route. JS lighting reads the authoritative `day_cycle`.
- `Persona` in main.luau owns 40 explicitly authored values/love/boundaries/conflicts and six stable 0–100 traits. Inspector and request use the same identity; never use traits as hard action overrides or claim they are generated thoughts, clinical scores, or proven model fidelity. They remain fixed this version. Model context ceiling is 1024 with no truncation; receipts retain exact input_state. Run isolated NanoJev Python on `tools/check-persona.py --live` to check all 40 actual inputs, plus offline/independence/token tests.
- Personal inventory is real: buying to carry transfers firm stock, `useItem` records consumption, and dead residents retain belongings. Audit `stock + carried == initial_stock + produced - consumed`. Tools are descriptive equipment, not a combat bonus. `check-life.py` tests execution with explicitly synthetic inputs.

- Use `tools/start-town.ps1`; model Python is the isolated ComfyUI/NanoJev/.venv-town environment. Do not upgrade the user's main ComfyUI environment.
- Verify `game check --types`, `game verify`, `game test`, `python tools/check-nanojev.py` (live), `python tools/check-economy.py`, `python tools/check-town.py`, and `node tools/check-camera.mjs`. `tests/evidence/nanojev-410-inputs.json` contains actual recorded model inputs, not hand-picked actions.
