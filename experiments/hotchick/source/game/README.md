## GoldSaucer 平台版

平台正式版支援心動幣、收藏存檔與多人共用盤面。卡包最多儲存 9,999 包、每次最多開 10 包並保留剩餘，舊存檔不清空。大型倍率 100～240、捕獲率約 0.57647%，有效投注理論 RTP 98%。最終上傳版本、作者預覽網址與審核狀態由當次平台報告記錄。

正常在途子彈可持續連射；在途與待結算合計硬上限為 64，待結算達 32 輪才因積壓暫停新槍。同一筆伺服器呼叫引起的 `chipsChanged` 依權威回覆配對，不再每輪重讀錢包或關閉射擊閘門；外部餘額變更仍待安全閒置時回讀與對帳。一般同步狀態持續 900 ms 才在左下顯示小型提示，提示可穿透點擊；錯誤、餘額不足與需要重新連線時仍保留明確操作入口。

平台身分已完成連結。後端採 JavaScript 伺服器函式 `open`／`settle`／`drawCards`／`saveProgress`／`roomDirectory`／`roomSnapshot`，由平台安全亂數與帳本處理捕獲、派彩、演出風格、卡包及卡片；房間腳本處理即時玩家進出與射擊轉送。同房盤面的種子、symbol 世代及存活狀態由伺服器共用文件管理，Luau 按同一份參數顯示與移動女孩，並處理射擊、碰撞及演出。伺服器驗證 canonical 目標與捕獲歸屬，幾何碰撞仍由前端判定。前端使用官方 Unone Web/Wasm runtime。

代幣為「心動幣」，**1 紅鑽＝50 心動幣**。`currency.autoBuyIn: true` 讓平台在每次入場將全部可用紅鑽換成心動幣，與已有心動幣相加。依目前平台契約，真正離開 GamePage 時由平台自動換回可支付的整數紅鑽；舊版 `autoCashOut: false` 已不控制離場行為，零頭或暫時無法支付的餘額仍保留可恢復。兌幣由平台執行，遊戲不自行執行自動 `buyIn()`；正式投注與派彩仍由函式回傳後交平台記帳。作者預覽使用持久的 `demo` 餘額，與 `paid` 正式代幣及收藏分開，不會動用紅鑽；初始 10,000 點，不會因重整再發一次。遊戲內切換房間留在同一個 GamePage，不會再次自動帶入、帶出或重新 `open` 財務工作階段。

正式模式中，每次新的手動下注嘗試因餘額不足失敗時，橋接層會以 `GoldSaucer.ui.alert(message, {title, okText})` 通知平台，同一次嘗試只通知一次。AUTO、背景重試與預覽不彈出平台視窗；缺少此 SDK 方法時沿用 HUD 原因提示。未以真人帳戶實測扣紅鑽，此版本仍須平台審核。

正式遊戲與作者預覽會由平台保存影片解鎖、已看大型影片、略過偏好、底注／武器偏好、各卡持有張數、總抽卡次數、卡包與進度、累計投注／獎金／結算輪數／捕獲數，以及最近一批開卡結果。重整後從伺服器恢復；抽卡紀錄採累計與最近一批，沒有每抽的無限時間序列。沒有 GoldSaucer SDK 的本機／內網試玩仍是本次頁面工作階段保存。接入契約、審核與上傳驗證見 `../assets/platform/goldsaucer/INTEGRATION.md`；最終雲端版本以當次平台上傳報告為準。

## 多人房間

房間入口提供房間列表、人數、建立房間及加入指定房間；每房沿用 DT2 的 **3 個座位**。同房玩家可看到彼此進出、砲台方向、武器與射擊。顯示的是實際連線玩家，不補假玩家，也不公開其他玩家的餘額、卡片或影片收藏。

同房共用 **27 個女孩 symbol：18 小、6 中、3 大**。伺服器保存房間種子、各 slot 的世代與出生時間；Luau 依相同參數還原游動，捕獲後所有玩家同步看到該世代消失與下一世代出生。同一世代只能成功捕獲並派彩一次，多人競爭時由伺服器原子交易決定歸屬。某輪所有目標都已失效時，全額退回預扣、不增加有效投注或卡包進度；部分目標失效時，保持整輪費用一次，按剩餘有效命中數均分獎金計算，回覆中的目標位置不重排。

切房先停止新射擊，讓舊房的在途子彈、待結算回覆及愛心收款完成，才提交新盤面；不以會凍結在途與收心的全域暫停等待。切換保留餘額、收藏、卡包、財務工作階段與結算識別。舊連線回覆會以房間世代判斷，不能覆蓋新房狀態；房間不存在、已滿或連線中斷時提供實際原因與重新選房流程。

即時連線由平台 gamehost／room runner 執行房間腳本；房間列表與共用盤面則由伺服器函式的持久共用文件管理。進度依玩家與遊戲保存，不依房間重開。正式與作者預覽、不同內容版本的房間各自隔離；免登入、頂層 `?trial=1` 與無 SDK 本地試玩維持單人，不加入真實房間。

## 免登入與獨立試玩

免登入玩家由平台初始化回應的 `trial: true` 進入本地 Luau 試玩，每次進入給 10,000 點。也可直接在頂層頁面開啟 `/play-content/<version>/index.html?trial=1`（將 `<version>` 換成實際版本）；這個明確的獨立試玩入口即使已登入也會略過 SDK，使用本地試玩，不呼叫真實錢包或伺服器函式。沒有 SDK 的本機／內網入口同樣使用本地玩法。正式 `paid` 與作者預覽 `demo` 的遠端結算、餘額及存檔規則保持原樣。

本地試玩點數不足時，可自行重新整理頁面，從新的 10,000 點開始。卡片、卡包、影片解鎖及偏好只保留本次頁面工作階段，重新整理或再次進入會一併清空本地進度，不會帶入平台正式或作者預覽存檔。

## 操作

- 遊戲固定以 16:9 橫向呈現。直向顯示轉向提示並禁止新投注與開卡，同時關閉 AUTO／瞄準；「心動時分」與卡片收藏的開卡入口同受 HUD 狀態門檻限制。轉回橫向須重新操作，不會自行續射或補打。在途子彈、演出與愛心收款照常完成。可點「橫向全螢幕」在支援的瀏覽器嘗試原生橫向鎖定。


- 未開瞄準的點讚：點盤面任意位置朝該方向發射，按住拖曳可轉向並每秒連射。普通子彈直線飛行，首次碰到女孩才命中；空白點不保證命中。
- 普通點讚 AUTO 保留最後射擊方向；只移動滑鼠而沒按住，不改變砲口方向。
- 瞄準、送花與火箭：點女孩選主目標，按住拖過另一女孩可換目標；空白點不更換目標。針對重疊目標，依 DT2 優先選可打且倍率較高者，試玩暫以各 symbol 倍率上限排序。
- 右側切換點讚 ×1、送花 ×6、火箭 ×15；發射時預扣一次底注乘倍率。有效命中才成立整輪投注，整輪落空或目標全部失效時全額退回，退款不計入有效投注或卡包進度。
- 點讚／瞄準每 0.12 秒一輪（約8.33輪／秒）、送花每4/15秒一輪（3.75輪／秒）、火箭每0.2秒一輪（5輪／秒）。火箭間隔依最新指示減半，成本仍是底注×15、每輪最多5個不同目標。射速與間隔收在測試工具中，切武器不繞過上一輪已排定的冷卻。
- 底部調整底注、瞄準與自動。鍵盤 1 / 2 / 3 切換武器，A 自動、L 瞄準、空白鍵送出。
- 開瞄準同時開 AUTO；手動關閉 AUTO 會真正停止連射，保留瞄準供手動使用。自然中獎、暫無目標或餘額不足時保留 AUTO 意圖，待可射擊後繼續，不補打等待期間的輪數。回顧與演出試看會停止 AUTO／瞄準。目標離場後優先找同種類、距上一位置最近者，其次找倍率最高的有效目標。
- 一般畫面不顯示試看或測試控制。在目前試玩網址加上 `?debug=1` 後，右上「工具」可預覽小獎、中型、滿版大獎及六支中型影片；不扣點、不派彩、不解鎖，執行前停止 AUTO 並關閉工具視窗。
- 右上「心動時分」視窗固定為遊戲區寬高的 88%，切換角色或播放影片時不變動；左側角色分頁與右側內容各自捲動。角色有介紹、影片與卡片三個頁籤；介紹使用遊戲設定文案。影片依風格列出實際提供的條目，不顯示空白獎項；同一風格可有多支中／大型影片，也可只有大型。未解鎖縮圖壓灰，點擊顯示條件；捕獲並實際開到該影片後可重播，不再次派彩。平台收藏保存在玩家對應模式的伺服器存檔；無 SDK 本機版暫存本次頁面工作階段。
- 主畫面的「略過已看大獎」首次預設關閉，平台重連時恢復已存偏好。完整播放過的自然大型演出或已解鎖大型影片回顧，才記錄為看過；手動略過、播放失敗、逾時與測試預覽不計。勾選後，下一次同一角色／風格的該支大型影片會直接接到愛心收款，首次影片仍播放。只略過演出，獎金與逐心入帳保持原規則；平台保存此設定與看過紀錄，無 SDK 本機版只保留本次開啟期間。
- 「說明」收納操作、投注與收藏規則；本機重設試玩收在獨立工具模式。本地與免登入試玩每次載入初始 10,000 點、底注 10；作者預覽 demo 沿用已存試玩餘額，平台正式餘額以心動幣帳本為準，遠端偏好會從存檔恢復。

## 本次素材

### 卡包與卡片收藏

左側能量條顯示下一包進度與目前卡包數，有包可開時會發光提示，點擊開啟獨立拆包介面。**最多儲存 9,999 包，每次最多開 10 包**；例如 3 包會一次抽出 3 張，有 11 包則先開 10 包、保留 1 包。每批結果可逐張欣賞或一次收起，未開卡包繼續保留。已成立有效投注結算的籌碼累計每滿 1,000 獲得一包，餘數進度保留；送花／火箭依整輪實際扣款累計一次。存滿 9,999 包時暫停累積，溢出投注與進度忽略，不另存、也不在開包後追補；開掉卡包後從新投注繼續累積。開卡不再扣籌碼，獎金入帳、演出試看與影片重播不增加進度。先抽稀有度 N／R／SR（70%／25%／5%），再從同稀有度全部已提供卡片中等機率選一張，可以重複，收藏顯示持有張數。平台由 `drawCards` 使用安全亂數決定卡片；無 SDK 本機版使用獨立卡片亂數序列，不消耗捕獲或演出風格序列。

本批 14 張：恩妃 N×2／R×2／SR×1、藝瑟 N×1／R×1／SR×1、嘉儀 N×1／R×1／SR×2、むぎ N×2；恩智尚無卡圖。N 為一般卡、R 為閃卡、SR 為鑽卡；收藏及結果依 SR／R／N 排序。卡片頁只保留收藏，不重複顯示投注累積說明。已持有卡片可打開滿版賞卡，只顯示卡片與上方返回，拖曳旋轉、雙擊或 F 翻面，滾輪縮放；0 可重設姿勢。微光背景搭配官方引擎粒子，最多 36 粒，尊重減少動態設定。大獎起手、影片及收心優先覆蓋賞卡，結束後保留原卡的角度及縮放。閃卡／鑽卡欣賞改用官方引擎編譯的 GLSL ShaderMaterial，在既有 WebGL renderer 呈現真正的雙面3D卡片；反光與彩虹隨旋轉改變，N維持一般卡。卡片不解鎖影片，也不派彩。

開包先蓄光、撕包，再出現卡背並逐張翻面，最後顯示排序後的本批結果；動畫節點最多 10 張，與儲存卡包總量分開。10包完整版本約4.4秒；減少動態模式仍保留約1秒的分段淡入，不再瞬間列出10張。

所有14張均可抽到，4張SR平分SR的5%，每張單抽機率為1.25%。平台抽卡由伺服器安全亂數處理，重試同次開包不重新抽取。無 SDK 的 Web 本機版每次開啟以 crypto.getRandomValues 建立獨立卡牌種子，經標準輸入交給 Luau，不消耗捕獲／風格亂數；原生測試未指定種子時保留固定序列供重現。

平台保存各卡持有張數、累計抽卡次數、卡包進度、累計有效投注與最近一批開卡；demo／paid 分開，重整後可恢復。無 SDK 本機版的收藏與累計資料只保留本次開啟期間，重新整理或重設本機試玩後清空。素材由獨立卡片工坊與 `assets/cards/recipe.json` 生成，原檔保留；卡圖統一為 600×900 WebP，遊戲效果及框線不烤入原圖。卡片工具啟動：`../Start-CardTool.ps1`，預設網址 http://127.0.0.1:8243/；支援鎖定 2:3 裁切、配方匯入匯出與批次生成。

## 模擬與待確認事項

無 SDK 本機版的點數、捕獲與派彩由 Luau 計算；GoldSaucer 平台版由 JavaScript 伺服器函式決定捕獲、派彩及演出風格，正式代幣由平台記帳。兩者採相同的有效投注理論 RTP **98%**：整輪費用在有效命中的目標間均分，整數尾差採無偏機率捨入。小／中／大型捕獲率為 24.5%／約 7.53846%／約 0.57647%。大型倍率改為 100～240，捕獲率為舊版四分之一；中小獎不變。整輪落空退回本機預扣，不成立投注、不增加卡包；此 RTP 以已成立的有效投注為分母。獎金隨愛心抵達逐步加入顯示／可用點數。數學與驗證說明見 `../assets/platform/goldsaucer/RTP.md`，平台接入見 `../assets/platform/goldsaucer/INTEGRATION.md`。平台尚未模擬盤面碰撞；火箭搜索半徑仍暫為標準小泡泡直徑的 3 倍（搜索圈直徑 6 倍），正式範圍待確認。

release-013 將每次命中的中型捕獲機率由 32% 降至 16%，大型由 20% 降至 10%；小型維持 40%。這是 symbol 捕獲機率，聖誕風格仍在符合門檻且成功捕獲後另抽 50%，獎金倍率不變。

送花已依確認規則：以主目標中心作直徑 3 倍小泡泡的圓，副目標中心在圓內才入選；隨機抽 2～5 個副目標名額，不放回，數量不足只命中現有目標，整輪仍扣 ×6。火箭主 1＋副最多 4，不重複。

射擊行為參考 DT2 現行 Lua：普通炮直射且首次真碰撞命中；前兩次碰壁反射，第三次碰壁且彈齡至少 0.5 秒便回收，另有 35 秒壽命。瞄準點讚追蹤指定目標；送花沿弧線追蹤，命中時以主目標當下位置抽圈內副目標；火箭飛向各目標在發射時的快照位置。射速亦採 DT2 `Player.lua:getShootCD` 的普通 .12、Axe .12/.45、Lightning .12/.3 秒，保留海王三種投注倍率。每輪的武器、底注與費用在發射時固定，中途切換武器不改動在途子彈。連射保留不足一幀的時間餘差，停火、回顧、大獎或無有效目標後不累積補打。

## 引擎與驗證

盤面移動、射擊碰撞、操作與前端演出狀態在 `scripts/main.luau`，使用官方 Unone Web/Wasm runtime。本機結算亦在 Luau；平台版改由 `server/goldsaucer/functions.js` 管理金融結算、演出抽選與持久收藏，Web adapter 串接 SDK 並把結果交回 Luau。為支援 WebP 圖集與影片 DOM overlay，選用 custom presentation module，仍委派官方 `createThreeRenderer` / `attachPresentation`，沒有另寫模擬引擎或 WebGL host。爆發光點使用 scene `particle_effects` 與官方 `api.particle.play`；心形 UI 的座標、階段與數量由 Luau 發布，DOM 負責呈現並將操作傳為標準輸入事件，派彩不依影片是否成功播放。心形節點會回收重用。
