# GoldSaucer 接入紀錄

更新日期：2026-11-13。遊戲名稱為「海王・心動時分」，遊戲代幣名稱為「心動幣」，兌換比例固定為 **1 紅鑽＝50 心動幣**。

## 平台身分與部署方式

平台帳號與目前 ChatGPT 身分已完成連結，插件可辨識已登入會員。先前「未登入」與缺少兌換 API 的阻塞已解除。

遊戲後端採 GoldSaucer 的 JavaScript **伺服器函式**保存每位玩家的財務與收藏，以及遊戲共用的 canonical 盤面；多人即時進出與射擊則由平台 gamehost／room runner 執行房間腳本。房間腳本不處理紅鑽或派彩。前端仍使用官方 Unone Web/Wasm runtime 執行 Luau，負責共用盤面還原、射擊、碰撞、演出排程與操作；Web adapter 負責 SDK、房間傳輸、媒體播放與呈現。

封裝設定使用：

```json
{
  "functions": "server/functions.js",
  "server": "server/room.js",
  "currency": {
    "name": "心動幣",
    "perDiamond": 50,
    "autoBuyIn": true
  }
}
```

來源為 `server/goldsaucer/functions.js` 與 `server/goldsaucer/room.js`，打包時放入上傳目錄的 `server/functions.js` 與 `server/room.js`。含伺服器邏輯的版本按平台當下審核模式處理；作者可使用平台提供的待審版本預覽。最終上傳與審核結果另見當次報告。

## 伺服器函式與結算界線

| 函式 | 職責 |
| --- | --- |
| `open` | 開啟玩家工作階段，恢復餘額及收藏，回傳工作階段識別與批次序號。重開頁面保留平台存檔。 |
| `settle` | 驗證投注與合法目標資料，以平台安全亂數決定捕獲、倍率、整數尾差與演出風格，回傳獎金、影片及更新後收藏；正式模式交由平台記帳。 |
| `drawCards` | 一次開啟目前卡包中的最多 10 包，保留剩餘；抽選 N／R／SR、卡片及重複張數，保存累計與最近一批結果。 |
| `saveProgress` | 保存已解鎖大型影片的看過紀錄、略過偏好與合法底注／武器設定，不接受前端自行新增卡片或解鎖。 |
| `roomDirectory` | 列出本內容版本的房間、更新呼叫者的房間租約或離開自己的租約；伺服器建立共用盤面，不改財務、收藏或獎表。 |
| `roomSnapshot` | 讀取目前房間 canonical 種子、slot 世代與出生時間，必要時推進自然離場世代；須有呼叫者有效且相符的房間租約。 |

`settle` 每批最多 10 輪，單輪點讚／送花／火箭最多 1／6／5 個不同目標；投注倍率為底注 ×1／×6／×15。前端會合併結算，避免每顆子彈各發一個請求；仍須遵守平台每位玩家每款遊戲的呼叫頻率與資料大小限制。

release-031 的原生在途與待結算合計硬上限為 64，待結算 `pending >= 32` 時才因積壓暫停新槍。正常長距離在途不再由 12 輪門檻中斷連射。同一筆 `server.call` 產生的 `chipsChanged` 會與權威回覆配對，不另讀錢包或關射擊閘門；外部餘額變更仍等安全閒置時回讀、對帳及確認原生閘門。

最近一批在相同工作階段與批次識別下重試，會回傳原結果，不重抽、不重扣、不重加卡包；同一識別改帶不同內容會拒絕，過舊批次亦會拒絕。開卡亦使用可重試識別，卡片與卡包數由伺服器管理。無效參數或餘額不足會在亂數與記帳前拒絕。

**實際盤面碰撞仍由前端 Luau 判定。** 多人模式的種子、symbol 存活世代、出生時間、種類及角色由伺服器管理與驗證；捕獲競爭也由伺服器原子裁決。伺服器尚未驗證每顆子彈的幾何碰撞，因此不能宣稱已具備完整的伺服器物理驗證。

有效命中才成立整輪投注；整輪落空或目標全部失效時，Luau 退回本機預扣，該輪不送成立結算、不增加卡包進度。已成立有效投注的理論 RTP 為 **98%**，整輪費用按實際有效目標數均分，整數尾差採無偏機率捨入。數學推導及既有 Luau 驗證見 `RTP.md`；平台伺服器採相同獎表與機率。

平台記帳與畫面收心分開：伺服器結果只結算一次，Luau 在愛心抵達時逐步增加顯示／可用點數，不因重播影片或視覺特效再次入帳。

## 多人房間、共用盤面與切換

每個房間最多 3 人。遊戲提供房間列表、建立新房、加入指定房間及切換房間；實際成員、座位、姓名、方向、武器與射擊由 `defineRoom` 腳本轉送，不用裝飾砲台冒充玩家，也不傳送其他玩家的代幣、卡片或影片收藏。

SDK 使用 `multiplayer.join()` 快速配房、`join({room: "new"})` 建新房，以及 `join({room: id})` 加入指定房間。平台沒有一般玩家可用的房間列表 API，因此以 `roomDirectory` 的遊戲共用文件提供列表，不使用管理員房間接口。每位會員只有自己的租約；姓名取自平台身分，45 秒未更新即不再列入人數。最多保留 16 個有有效租約的房間，每房最多 3 人，將共用文件與回覆維持在平台 64 KiB／16 KiB 限制內。`buildId` 以 `hc-rooms-v1:<內容版本>` 分隔版本，列表、租約、盤面讀取與結算都須吻合；作者預覽的共用文件由平台另行隔離。

同房共用 27 個 slot：1–18 小型、19–24 中型、25–27 大型。伺服器以平台安全亂數建立種子，各 slot 保存世代及出生時間，Luau 按相同的確定性參數還原位置。邏輯目標識別為 `generation * 32 + slot`，自然離場推進世代；成功捕獲推進世代，1,200 ms 後重新出生。`roomSnapshot` 與成功結算回覆的 `board` 是盤面依據。WebSocket 的 `fieldDirty` 只提示需要重讀，不能以客戶端訊息改盤面或宣稱捕獲。

多人 `settle` 帶入 `roomId`／`buildId` 並驗證呼叫者租約、目標世代、種類與角色。共享文件與玩家狀態、籌碼由平台原子提交；同一世代只有一位捕獲者能得到獎金，衝突時重試整筆呼叫。已被其他玩家捕獲或自然離場的目標不再抽獎。整輪皆失效時，回傳 `refunded: true`、`cost: 0` 與空目標陣列，原生退回預扣且不增加有效投注、結算輪數或卡包進度。部分有效時，回覆保留原目標順序，失效項目 `eligible: false` 且獎金為零，整輪費用仍只成立一次，以剩餘有效目標數均分計算；傳輸以 active mask 保留對應位置。有效投注的成本、獎表、理論 RTP 98% 與 1:50 兌換比例不變。

切房先設獨立的新射擊閘門，讓舊房在途子彈、原生／Web 結算 ACK、演出與愛心入帳完成，再提交新房盤面並離開舊連線。不能用會停住子彈與收心的 `PlatformPause` 做排空。切換保留玩家餘額、收藏、卡包、財務 session 與批次／封包識別，不重設整個遊戲，不再呼叫財務 `open`，也不重載 GamePage。`join` 本身不會離開舊 socket，橋接層須明確清理舊連線並忽略舊房回覆，避免覆蓋新房。

`room.state` 與成員連線是暫態；canonical 盤面及房間租約存在伺服器函式的 `ctx.shared`，個人財務與收藏仍存在每位玩家的 `state`。所有 `server.call`，包括房間目錄、盤面、投注及存檔，共用同一個序列化佇列，避免每位玩家一次只允許一筆呼叫的衝突。房間腳本不直接讀取帳本或呼叫伺服器函式。

免登入、明確頂層 `?trial=1` 與無 SDK 本地模式維持單人 10,000 點試玩，不加入房間。已登入的作者預覽可使用該內容版本隔離的多人房間，仍只扣除持久 demo 點數，不動用正式籌碼。

## 代幣帶入、帶出與試玩隔離

`currency.autoBuyIn: true` 讓平台在每次入場時將全部可用紅鑽按 1:50 換入，與已有心動幣相加。依目前平台契約，真正離開 GamePage 時由平台自動換回可支付的整數紅鑽；舊版 `autoCashOut: false` 已被忽略。零頭或莊家暫時無法支付的餘額保留，按平台恢復流程處理，不會丟棄。這是平台的入場／離場處理，遊戲不自行呼叫自動兌幣，也不能直接修改紅鑽或平台餘額。手動帶入／帶出仍由 `GoldSaucer.chips.buyIn()`／`cashOut()` 交平台處理。

遊戲內切換房間只換房間連線與盤面，留在同一個 GamePage，不觸發離場或再次兌幣。正式模式的餘額與收藏沿用目前財務工作階段。

正式模式由函式回傳 `chips: { bet, win }`，平台維護玩家籌碼及莊家錢包帳務；帶出以整數紅鑽支付，不足 1 紅鑽的餘額留在遊戲。兌換比例及莊家錢包限制以平台契約為準。

平台作者預覽回應帶有 `preview: true` 時，遊戲使用 `demo` 模式，以伺服器保存的 10,000 點初始試玩餘額遊玩，函式回傳零平台扣款／派彩。正式遊玩使用 `paid` 模式與平台心動幣。兩種模式的收藏及累計資料分開，平台本身的預覽與正式狀態亦分開；試玩成果不會帶入正式代幣帳或正式收藏。

## 免登入與獨立本地試玩

嵌入平台時，`GoldSaucer.init()` 回傳 `trial: true` 代表免登入本地試玩；橋接層先暫停遊戲，確認初始化模式後才決定是否建立遠端結算器。此模式由 Luau 本地結算，每次入場給 10,000 點，不建立遠端結算器，也不呼叫真實錢包或伺服器函式。正式 `paid` 與作者預覽 `demo` 繼續使用原有遠端流程及各自的持久存檔。

頂層頁面的明確入口為 `/play-content/<version>/index.html?trial=1`，其中 `<version>` 使用實際內容版本。即使玩家已登入，這個入口也略過 SDK 初始化，直接進入本地試玩；它不是作者預覽網址。沒有 SDK 的本機／內網入口亦維持本地模式。

本地試玩點數不足時，由玩家自行重新整理頁面，從新的 10,000 點開始。前端讀取的 `game.trial` 僅提供 `enabled` 與 `initialBalance`。本地資金守恆維持 `balance = 10000 - spent - reservedWager + won` 與 `balance = displayBalance + pendingWin`。

卡片初始化種子可在啟動暫停期間接收，仍只初始化一次，不會重設已使用的卡片亂數流。本地試玩的卡片、卡包、解鎖及偏好只保留本次頁面，重新整理或再次進入會從新的 10,000 點與本地進度開始，不寫入平台收藏。

## 玩家存檔範圍

GoldSaucer 伺服器保存每位玩家在正式 `paid` 與作者預覽 `demo` 中的下列資料；本地試玩不在此存檔範圍：

- 實際開出的精確影片解鎖、完整看過的大型影片及略過偏好。
- 底注與武器偏好。
- 各卡片持有張數、總抽卡次數、目前卡包數與下一包進度。
- 累計已成立投注、獎金、結算輪數與捕獲次數，以及最近一批開卡結果。

每滿 1,000 已成立投注獲得一包，**最多儲存 9,999 包、每次最多開 10 包**。每批只扣實際開啟的包數，剩餘保留；例如 11 包開一次剩 1 包，9,999 包連開兩次剩 9,979 包。滿 9,999 包後停止累積，溢出投注與進度忽略、不追補，開包後由新投注繼續。抽卡為 N／R／SR＝70%／25%／5%，同稀有度內等機率且可重複；一批最多使用 20 次亂數，不因儲量增大而產生更多卡片。只有伺服器捕獲結果可增加影片解鎖，只有有效投注可增加卡包。

重整或重新連線可恢復上述平台資料；保存的是**累計收藏、統計與最近一批**，沒有建立每次抽卡的無限時間序列。正式代幣交易帳由平台維護。沒有 GoldSaucer SDK 的本機／內網試玩仍只保存本次頁面工作階段，重新整理或重設本機試玩會清空該工作階段資料。

`scripts/package-goldsaucer.py` 從官方匯出版本產生上傳目錄及 ZIP，加入伺服器函式、房間腳本與平台設定，移除重複匯出副本並保留授權檔。必要影片僅在上傳副本轉碼，維持原解析度與片長。

函式單元測試入口為 `node --test server/goldsaucer/functions.test.mjs`，涵蓋驗證、重試去重、demo／paid 記帳、RTP 數學及收藏存檔；平台實際沙箱驗證入口為 `server/goldsaucer/platform-runtime.test.mts`。報告位於 `artifacts/goldsaucer/qa/`，需與待交付版本一起檢查。

多人後端的針對性驗證入口為 `server/goldsaucer/rooms.test.mjs` 與 `rooms-runtime.test.mts`；本機官方 player 的合成多人傳輸由 `scripts/qa-rooms-fixture.mjs` 提供。這些入口不等於已驗證雲端部署；當次瀏覽器驗證、上傳及審核結果由發佈紀錄另行補上。

平台限制為 200 MiB 總量、20 MiB 單檔、2,000 檔、100 MiB ZIP。完成平台上傳後須讀取 `upload_report`，確認版本、作者試玩網址與審核狀態；最終雲端版本結果由本次發佈紀錄補上。
