# 工作包：老虎機作為商品，用來檢視引擎

日期：2026-09-06。計畫代理：Claude（主代理）。實作：codex / luna。
基準：`master` 的 `5eaed77`。狀態：`planned`（尚未實作）。

## 目的

把老虎機做成**一個真的可以出貨的商品**：完整美術、完整音效、完整操作回饋，
不是一個證明某個 API 存在的 fixture。

理由不是要做遊戲。是因為 fixture 逼不出來的缺口，只有商品逼得出來。目前兩次
盲測的結論都是「引擎能力夠，摩擦在發現性」——但那兩款是老虎機與小瑪莉的
**功能骨架**，幾乎不需要任何呈現能力。憤怒鳥一做成真的遊戲，立刻就撞出碰撞
事件、摩擦力、實體移除三個缺口。

所以這個工作包的產出有兩份：一個商品品質的遊戲，以及**一份它撞到的引擎缺口
清單**。後者才是主要交付物。

## 設計精神（適用本包每一段）

有實務需求時，**先留有彈性的空缺，不要寫死**；只有現在真的要用到，才去具體
實作。

對實作者的意思是：

- 撞到引擎缺口時**回報，不要在遊戲端造替代品**。造了替代品，這個工作包就
  什麼都沒找到，而且那段替代碼日後要拆。
- 需要一個引擎沒有的能力時，主代理會判斷是「補一個空缺」還是「現在就實作」。
  例如音訊的分類規則：宣告結構現在就進契約，但只實作老虎機真的要用的三條，
  其餘保留並在被宣告時明確報「本 build 未實作」。
- 文字一律走 `text_key`，即使現在只有一種語言——那是同一個原則的另一個例子：
  空缺留好，加語言時遊戲程式碼一行都不用改。

## 商品驗收標準

由人以「這能不能上架」的標準判斷，不是由 gate 判斷。至少要有：

**視覺**
- 轉輪符號是真正的老虎機符號美術，不是別的遊戲的範例角色。
- 有機台外框／背景，不是純色底 + 文字。
- 轉動時看得出在轉（連續捲動或逐格切換），不是數字瞬間跳變。
- 按鈕有可按／按下／不可按三種外觀。
- 中獎有明確的視覺慶祝，且與非中獎明顯不同。

**聽覺**
- 拉桿、每一軸停止、中獎、按鈕各有音效。
- 有背景音樂，且切換時會淡出淡入。
- 靜音或音訊未解鎖時遊戲仍可玩。

**操作**
- 押注額可調整。
- 有自動連續遊玩。
- 分數變化看得出來（不是瞬間跳到結果）。
- 存檔還原後回到同樣的分數與上一局結果。

**版面**
- 16:9 與直式手機比例都不破版（用 anchor，不是兩套絕對座標）。
- 每一個畫面狀態都通過 `ui preview --strict`。

## 預測會撞到的引擎缺口

這是本工作包的**計畫價值**：先寫下我預測會撞到什麼，實作時逐一確認或推翻。
實作者遇到時**回報，不要繞過**——繞過會讓這次練習失去意義。

| # | 商品需求 | 引擎現況 | 預測 |
|---|---|---|---|
| 1 | 全部音效與 BGM | **完全沒有** | 一定撞到。[音訊工作包](2026-09-06-audio.md)已規劃，未實作 |
| 2 | 轉輪連續捲動 | 只有 Spine 骨骼動畫，**沒有 sprite frame/UV 動畫** | 一定撞到。roadmap #22 有列但沒有契約 |
| 3 | 按鈕三種外觀、數字樣式、中獎高亮 | UI 節點**只有 text/button + rect**，沒有任何樣式詞彙 | 一定撞到。修飾層（圓角／漸層／outline／陰影）討論過但從未寫成工作包 |
| 4 | 分數滾動、畫面轉場、待機動畫 | **沒有計時器／tween**，每款遊戲自己數 frame | 很可能撞到。roadmap #4 |
| 5 | 機台外框在底、符號在上、特效最上 | `sprite.layer` core 已有，**host 排序未接** | 撞到，但已在 2D transform 工作包進行中 |
| 6 | 直式手機不破版 | anchor 已交付，**沒有任何遊戲用過** | 這是 anchor 的第一次實戰，預期會發現問題 |
| 7 | 文字（分數、賠付表、提示） | **native 完全不畫 UI**，Web 才有 | 撞到，但屬 P4 平台缺口 |
| 8 | 多語系 | 引擎沒有字串表概念 | 已決定：**先單一語言，但接縫先做**，見[接縫工作包](2026-09-06-localization-seam.md) |

第 8 項是我在寫這份計畫時才發現的漏項。使用者裁示先做單一語言、架構先備好，
因此對本工作包的要求是：**所有顯示文字走 `text_key`，不得直接寫字面字串**。
成本只是把字串搬進一個 JSON 檔，換到的是之後加語言時遊戲程式碼一行都不用改。

## 分段

### 第 0 段：先修間歇性假失敗的 gate

**其他所有段落在此之前不算數。**

實測同一個未修改的專案連續執行 `verify` 七次，其中一次 `types` 回報
`failed`，其餘六次 `passed`；單獨執行 `game check --types` 永遠 `ok: true`、
`output` 為空。

一個會偶爾假失敗的 gate 會教作者「重跑到綠為止」，那個習慣一旦養成，本工作包
產出的每一份「全綠」證據都不可信。

要求見 [issue](../issues/2026-09-06-verify-types-step-flaky.md)：先連跑 50 次
量出失敗率並保存每次完整 diagnostic，再分辨「工具沒跑起來」與「型別真的有
問題」，回歸測試要能證明前者不會被誤報成後者。

語言範圍已裁示：單一語言，接縫先備。`ui_previews` 的 `load_save` 已判定要支援，見[該工作包](2026-09-06-ui-preview-load-save.md)；
但老虎機的 `restored` 畫面結構與 `ready` 完全相同（同 7 個節點、同 rect，只有
文字不同），所以把它納入 layout gate 對這款遊戲一無所獲。不要用它當那個欄位
的價值證明。

### 第 1 段：資產取得與授權

依 [交接文件](../ai-agent-game-handoff.md) 的既有政策從 itch.io 取得美術與
音效。**每一項資產都必須記錄**：來源 URL、作者、授權條款、取得日期、
attribution 要求、使用到的檔案、hash。授權不允許打包或公開展示的，回報後
換掉，不要猜。

不要為了某個資產悄悄擴充引擎（例如為了一個 `.aseprite` 檔就加一個匯入器）。
格式限於現有 host 支援得了的；不支援就換資產或回報。

現有的 Spine `spineboy` 是官方範例，不是本遊戲美術，必須換掉或明確標示。

### 第 2 段：能做的先做完

在音訊與樣式層落地之前，先完成不依賴它們的部分：真實符號美術、機台背景、
layer 分層宣告、押注額、自動遊玩、直式與橫式的 anchor 版面、每個畫面狀態的
`ui_previews`、鏡頭宣告。

每完成一項就跑 `verify`，並把當下撞到的引擎缺口寫進缺口清單。

### 第 3 段：等待中的能力

音訊（#1）、frame 動畫（#2）、UI 樣式（#3）、計時器（#4）尚未交付。實作者
**不要自己在遊戲端造替代品**——那正好會掩蓋掉這個工作包要找的東西。遇到就
停在那裡、寫進缺口清單、繼續做別的。

主代理會依缺口清單決定各自的工作包順序。

### 第 4 段：證據

`validation/` 下建立：`baselines/spin.recording.json`（replay 基準）、
`perf.md`（600 frames）、`assets/licenses.md`（第 1 段的記錄）、
`validation-report.json`（每一條命令的真實結果，失敗也記）。

並示範工具真的有用：故意改一個賠付數字，跑 `replay diff`，把它指出的第一個
分歧 frame 與欄位貼進報告，然後還原。

### 第 5 段：缺口報告（主要交付物）

`validation/engine-gaps.md`，逐項記錄：

- 撞到的是什麼商品需求；
- 引擎缺什麼，用哪一條命令與哪一段輸出證明；
- 有沒有繞過（有的話說明繞法與代價）；
- 上表的預測哪些成立、哪些是我猜錯的。

**猜錯的部分特別重要**——那代表我對引擎現況的理解有誤。

## 不做

- 不加 slot 專用的引擎 API。賠付、轉輪、比倍、押注全是遊戲端規則。
- 不為了湊能力而打開用不到的系統。這款遊戲正確地關掉了 `physics2d`。
- 不改引擎契約來遷就這款遊戲。發現缺口回報，由主代理另立工作包。
- 不購買任何付費資產，不猜授權。

## 驗收

商品標準由使用者判斷。工程標準：

```powershell
game --project D:/Projects/Unone_Games/slot-machine --json verify
game --project D:/Projects/Unone_Games/slot-machine --json asset inspect --strict
game --project D:/Projects/Unone_Games/slot-machine --json perf --frames 600
game --project D:/Projects/Unone_Games/slot-machine replay diff --baseline validation/baselines/spin.recording.json
```

加上 `verify` 連續 50 次全綠。

`validation-report.json` 必須明確標示**尚未取得的證據**：native 音訊、native
UI 與文字、Android 畫面、Spine／Effekseer 在 native 的呈現，目前全部沒有。
Web 通過不等於跨平台通過。
