# 工作包：音訊語意層

日期：2026-09-06。計畫代理：Claude（主代理）。實作：codex / luna。
基準：`master` 的 `74c6d37`。roadmap 項目 **P0 #1**。
狀態：`planned`（尚未實作，尚未取得任何證據）。

## 與 `2026-09-06-minimal-audio.md` 的關係

工作樹另有一份 `2026-09-06-minimal-audio.md`（另一代理，未提交），它的
Web-first 分段、bundle 位元組取得、autoplay 阻擋回報、one-shot 自然結束由 host
處理，都比本文件原稿具體，**以它為基底**。

但它明確排除 categories、fades、cross-fade 與 music policy，而老虎機的商品
規格要求「背景音樂切換時淡出淡入」。兩者衝突，由主代理裁定如下：

- **形狀採用它的**：`audio.events`（帶 `kind: play|stop` 與 handle）與
  `audio.active_loops`；one-shot 的自然結束由 host 處理，不回寫 world。
- **規則機制保留為空缺**：分類與規則的**宣告結構**要做進契約，但**只實作
  現在用得到的三條**。
- 這符合設計精神：有實務需求就先留有彈性的空缺，不寫死，等到真的要用才
  具體實作。

本文件的 snapshot 範例與 API 若與該文件不同，以該文件為準；本文件負責的是
**分類與規則的空缺形狀**，以及它為什麼現在只實作三條。

## 為什麼是 P0

引擎目前**一個音訊 API 都沒有**（`grep audio` 在 `crates/unone-engine/src/`
與 `docs/scene.schema.json` 皆零命中），所有驗證遊戲都是靜音的。七款 final
gate 沒有一款能在無聲的情況下算完成。這不是「某款遊戲需要」，是一般引擎的
基本能力，適用 roadmap 判斷標準第 1 條。

## 邊界

引擎擁有：**播什麼、什麼時候播、以什麼語意參數播**，以及它的 determinism。

引擎**不**擁有：解碼、混音、重採樣、空間衰減曲線、ducking、crossfade、
音量設定 UI、以及「這個一次性音效播完了沒有」。最後一項是刻意的，見下節。

不做：音訊匯入或轉檔（走 roadmap #8 的 pipeline）、DSP 效果、音軌
timeline、以及 master/bus 音量。**玩家音量設定是 host 與玩家的事，不是遊戲
狀態**；引擎只傳遞「這個聲音以遊戲語意音量 0.8 播放」，實際輸出音量由 host
乘上玩家設定。

## Core contract

### 兩種發布形狀

引擎不知道任何 clip 的長度，也不打算知道（要知道就得解碼，或要求 manifest
宣告一個引擎無法驗證的常數——那正是 [Decision 0029](../decisions/0029-text-layout-gate.md)
禁止的猜測）。因此一次性與循環分成兩種形狀，各自對應引擎**已經有**的模式：

| 形狀 | 語意 | 生命週期 | 對應既有欄位 |
|---|---|---|---|
| `audio.events` | 這一幀發出的 play／stop 意圖 | 每幀重建，只出現一幀 | 同 `world.contacts` |
| `audio.active_loops` | 正在循環的音源 | 有 handle，持續到被停止 | 同 `world.effects` |

（欄位名以 `minimal-audio` 為準；本文件早先寫成 `audio_events` /
`audio_sources`，以下範例同樣以該文件為準。）

一次性音效因此不需要引擎知道長度：它只是「在第 N 幀觸發」的事件，host 播完
自己丟掉。循環音源有 handle，遊戲負責停止。

### Snapshot shape

`WorldSnapshot` 新增兩個欄位，兩者皆 `skip_serializing_if` 為空，因此沒有用
音訊的遊戲 digest 不變：

```json
{
  "audio_events": [
    { "asset": "audio://sfx/launch", "volume": 1.0, "speed": 1.0,
      "position": { "x": 2.0, "y": 1.0 }, "frame": 61 }
  ],
  "audio_sources": [
    { "handle": "audio-1", "asset": "audio://music/theme", "volume": 0.6,
      "speed": 1.0, "position": null, "started_frame": 0 }
  ]
}
```

欄位與驗證：

| 欄位 | 型別 | 未宣告時 | 驗證 |
|---|---|---|---|
| `asset` | `string` | 必填 | 非空；不檢查它在 manifest 內（`asset inspect` 的職責） |
| `volume` | `number` | `1.0` | 有限、`0.0..=1.0`，超界回傳 runtime error |
| `speed` | `number` | `1.0` | 有限、`> 0`；用於音高／變化 |
| `position` | `Vec2?` | `null` | 有限；`null` 表示非空間音效。引擎**不**計算衰減 |
| `frame` / `started_frame` | `u64` | 引擎填 | 觸發／開始的 frame |

`audio_events` 每幀在 tick 開始時清空，與 `contacts` 相同時機。

### 分類與規則

音訊真正的複雜度不在「播一個聲音」，而在**互相之間的規則**：BGM 換曲時前一
首要淡出、新的一首要淡入；同類音效同時只能有幾個；語音播放時要獨佔。這些
規則若留給每款遊戲自己寫，每款都會寫一次而且寫得不一樣。

引擎**不**內建 `bgm` / `sfx` 這些名字——那是遊戲的分類法。引擎提供的是
**宣告分類並附規則**的機制，規則本身是引擎擁有的封閉集合。

專案在 `project.unone.json` 宣告：

```json
"audio": {
  "categories": {
    "bgm":   { "exclusive": true, "fade_in_frames": 30, "fade_out_frames": 30 },
    "sfx":   { "max_concurrent": 16, "on_limit": "drop_oldest" },
    "voice": { "exclusive": true, "fade_out_frames": 6 }
  }
}
```

### 現在實作哪些、保留哪些

依「現在用得到才具體實作」：

| 規則 | v1 | 為什麼 |
|---|---|---|
| `exclusive` | **實作** | 老虎機的 BGM 切曲需要它 |
| `fade_out_frames` | **實作** | 商品規格明寫「切換時淡出」 |
| `fade_in_frames` | **實作** | 同上，淡入 |
| `max_concurrent` | 保留 | 老虎機同時音源少，現在用不到 |
| `on_limit` | 保留 | 沒有 `max_concurrent` 就沒有它的意義 |
| ducking、priority、群組互斥、空間衰減 | 保留 | 都沒有實際需求 |

**保留的意思是：宣告結構容得下它，但這個 build 沒有實作。** 宣告一個保留中的
規則名稱時，回傳明確錯誤並列出「這個 build 實作了哪些」——不是靜默忽略，也
不是假裝生效。靜默忽略一個規則，遊戲會以為自己設定好了，那是最難查的錯。

加一條規則就是加一個欄位與一段實作，既有宣告不受影響。這是空缺，不是待辦。

### 三條規則的語意

| 規則 | 型別 | 預設 | 語意 |
|---|---|---|---|
| `exclusive` | `bool` | `false` | 同一分類同時只有一個 loop。開新的會讓舊的進入停止流程 |
| `fade_in_frames` | `u32` | `0` | 新 loop 的淡入長度 |
| `fade_out_frames` | `u32` | `0` | 停止時的淡出長度 |

**淡入淡出由引擎以 frame 計數擁有，實際音量斜坡由 host 做。** 引擎不知道 clip
長度，但它完全知道「第 120 幀開始淡出、30 幀後移除」——那是 frame 算術，不是
音訊解碼。淡出中的 loop 仍留在 `active_loops`，帶著狀態：

```json
{ "handle": "audio-3", "asset": "asset://audio/music/lobby", "category": "bgm",
  "volume": 0.6, "started_frame": 10,
  "state": "fading_out", "state_started_frame": 120, "state_frames": 30 }
```

`state` 是 `"starting"`、`"playing"`、`"fading_out"`。淡出結束的那一幀，引擎
把它從清單移除——deterministic，不需要 host 回報。

沒有宣告任何 fade 的分類，`state` 恆為 `"playing"`，行為與沒有分類時相同。

### 為什麼規則放引擎而不是遊戲

因為它們**改變狀態**：哪個音源還在、哪個被停掉，是 deterministic replay 與
digest 的一部分。若交給遊戲各自實作，同一份輸入在不同遊戲會產生不同的
「還有哪些音源在播」，那就不再是可斷言的事實。

規則集合刻意保持封閉且小。之後要加新規則（例如 ducking、priority、
categories 之間的互斥）都是**加欄位**，既有宣告不受影響——這是留給擴充的
接縫，不是現在就要做的東西。

### Luau API

```luau
export type AudioOptions = {
    volume: number?,    -- 0..1, default 1
    speed: number?,     -- > 0, default 1
    category: string?,  -- 覆寫 asset manifest 宣告的分類
    x: number?,         -- 省略 x 或 y 即為非空間音效
    y: number?,
}

export type AudioApi = {
    play: (asset: string, options: AudioOptions?) -> (),        -- 一次性
    loop: (asset: string, options: AudioOptions?) -> string,     -- 回傳 handle
    stop: (handle: string) -> boolean,
    stopAll: () -> number,                                       -- 回傳停掉幾個
}
```

`play` 不回傳 handle：一次性音效沒有可被引擎追蹤的生命週期，回傳一個永遠
無法查詢的 handle 只會誤導。`loop` 回傳 handle，格式 `audio-<n>`，`n` 依
建立順序遞增，因此相同輸入產生相同 handle。

`stop` 觸發的是分類規則定義的停止流程：有 `fade_out_frames` 的分類會進入
`fading_out` 狀態並在指定幀數後移除，沒有的立即移除。因此 `stop` 回傳
「有沒有這個 handle」，不代表「已經沒聲音了」。

全域同時 loop 上限 **64**（`effects` 是 256），超限回傳 error 而非靜默丟棄。
分類層級的 `max_concurrent` 是保留規則，本 build 不實作。

### Determinism

音訊狀態**進入** observation digest，與 perf 量測相反：一款播了不同聲音的
遊戲處於不同狀態，測試必須抓得到。因此：

- 相同 seed 與輸入必須產生逐幀相同的 `audio_events` 與 `audio_sources`。
- 新增 `audio` test assertion，做完整 JSON equality，與既有
  `animation` / `effects` assertion 同一個習慣：
  `{"audio": {"events": [...], "sources": [...]}}`。
- host 播放與否、玩家音量、輸出裝置都不進 snapshot。

### System

新增 system `audio`，`optional: true`，`default_enabled: false`。

**狀態必須是 `available`，不是 `host_required`。** 本工作包必須包含至少一個
真的會發出聲音的 host（見下節）。Spine／Effekseer 已經示範過「宣告了但沒有
任何 host 會播」的後果——盲測代理花了時間去接一個沒人實作的能力。不重蹈。

關閉時 `api.audio` 回報 `SYSTEM_DISABLED`，snapshot 不含兩個欄位。

### Asset

`is_supported_asset_kind` 新增 `"audio"`。單檔資產，不需要 `files` companion。
引擎不解碼、不驗證格式；`asset inspect` 照既有規則檢查 id／source／bundle。
建議格式由 host 能力決定，文件說明 Web host 走 `decodeAudioData`，因此
`.ogg` / `.mp3` / `.wav` 由瀏覽器決定支援度——**引擎不宣稱格式支援清單**。

| `crates/unone-engine/src/asset.rs` | `is_supported_asset_kind` 加 `"audio"`；錯誤訊息同步 |
| `crates/unone-engine/src/api.rs` | `audio.play`／`audio.loop`／`audio.stop`／`audio.stopAll` descriptors，含 `common_errors` 與 `frame_semantics` |
| `crates/unone-engine/src/engine.d.luau` | `AudioOptions`、`AudioApi`、`EngineApi.audio` |
| `crates/unone-engine/src/project.rs` | `AudioAssertion`；`TestAssertion` 新增 `audio` 欄位 |
| `crates/unone-engine/src/runtime.rs`（assertion） | `evaluate_assertion` 的 `audio` 分支 |
| `docs/engine.d.luau` | 由 `game api typings --output` 產生，不手改 |
| `docs/test.schema.json` | `audioAssertion` 定義與 `assertion` 的 `oneOf` 變體 |

**不要碰**：`diff.rs`、`layout.rs`、`performance.rs`、`verify.rs`、任何 host
檔案、以及 2D transform 工作包正在寫的 `world.rs` 區段以外的欄位。若與 2D
transform 工作包在 `world.rs` 產生衝突，以該包先落地為準，本包後接。

core unit regression（同檔測試）：

1. 預設關閉：未宣告 `systems.audio` 時 `api.audio.play` 回報 `SYSTEM_DISABLED`。
2. 開啟後一次性事件只出現在觸發的那一幀，下一幀消失。
3. 循環音源持續存在，`stop` 後消失；handle 依序 `audio-1`、`audio-2`。
4. `volume` 超界、`speed <= 0`、非有限數、空 asset 皆回傳 runtime error 且
   **不留下部分狀態**。
5. 超過 64 個循環音源回傳 error，不靜默丟棄。
6. `exclusive` 分類：開第二個音源時，第一個進入 `fading_out`，並在
   `fade_out_frames` 之後的那一幀從清單消失——用 frame 精確斷言，不是「大約」。
7. `max_concurrent` + `on_limit`：`drop_oldest` 丟最舊的、`drop_new` 拒絕新的、
   `error` 回傳 runtime error；三者各一個 test。
8. 未知的分類規則名稱、未宣告的分類名稱皆回傳錯誤並列出合法值。
9. 相同 seed 與 input sequence 兩次 run 的 `audio_events` 與 `audio_sources`
   （含 `state` 與 `state_started_frame`）逐幀相同。
10. 沒有用音訊的既有場景 snapshot digest **不變**（`skip_serializing_if` 生效）。

## 驗收 gate

core 與 Web 兩段都完成後：

```powershell
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
game --project <game> --json systems list      # audio: available
game --project <game> --json verify            # 全綠
game --project <game> --json asset inspect --strict
```

再加一個**真實遊戲證據**：老虎機加上拉桿與中獎音效（它已有 Spine／Effekseer
表現層，是最短路徑），提供

- `audio` assertion 釘住拉桿那一幀的事件與中獎那一幀的事件；
- `replay diff` 證明只改音量時，第一個分歧 frame 與欄位被指名；
- Web host 實測有聲，並如實記錄「native 與 Android 無聲」。

## package-only 盲測企劃（本包完成後另案指派）

代理只收到 immutable package、一份要求「發射有聲、命中有聲、勝利有背景音樂
且可停止」的 `GAME_PLAN.md`、空目錄。必須回報：

- 是否能只靠 `api search "sound"` / `systems list` / `api describe` 找到音訊
  能力，而不需要猜；
- 一次性與循環的分界是否自明，或它是否誤以為 `play` 會回傳可停止的 handle；
- `audio` assertion 是否足以在無法聽聲音的情況下證明音效正確；
- 錯誤訊息（超界 volume、超過上限、system 未開）是否指出下一步。

## 待使用者決定

1. **循環音源全域上限 64** 是我定的數字，理由是超過幾十個同時循環必然是

## 留給擴充的接縫

使用者要求保留彈性。以下是本包**刻意留下但不實作**的擴充點，加它們都是加
欄位，不動既有宣告：

- **保留中的規則**：`max_concurrent`、`on_limit`、ducking、priority、分類
  互斥群組。宣告它們目前回傳「本 build 未實作」的明確錯誤。
- **空間音訊**：目前 `position` 只是傳給 host 的事實，引擎不算衰減。之後若要
  引擎擁有衰減曲線，那是加一個分類規則，不是改 API。
- **音訊資產的 companion files**：目前單檔；若之後需要 sprite-sheet 式的音訊
  bank，走既有 `AssetSpec.files`。
- **runtime 改分類規則**：目前規則是 project 宣告、整場不變。若遊戲證明需要
  在 runtime 調整（例如選項畫面），再另立 API 契約。

不做的仍然不做：DSP 效果鏈、音軌 timeline editor、master/bus 音量 UI。
