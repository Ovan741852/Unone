# Job compilation cache — 2026-09-08

The executor now reuses internally compiled bytecode, with an exact-source LRU
bounded to 32 entries and 1 MiB per execution thread/WASM instance. VM creation,
module initialization and buffer copies remain per job. No game logic moved to
Rust. Fresh globals/upvalues and current file paths are covered by tests.

## Release measurements

Before and after are real production WASM artifacts with matching feature sets.
Same 4 KiB input and source; three alternating pairs of 40 warm calls, byte-exact
output assertions. Median of the three round means:

| Kernel | Before ms | After ms | Change |
|---|---:|---:|---:|
| Minimal buffer read/write | 0.168 | 0.216 | 28% slower, no demonstrated gain |
| 128 arithmetic statements | 0.352 | 0.147 | 58% less time |

Small-call results are sensitive to JIT/GC and instrumentation. This does not
establish a win for every job or a game FPS improvement. Cold calls and all raw
samples are included in [evidence](2026-09-08-job-cache-evidence.json), along with
artifact hashes. The after artifact includes the new profiling overhead.

## Validation and decision

Engine: 225 passed, 3 ignored. Web ABI: 10 passed. Shared JS: 19 passed.
Production browser: 30 ticks match across inline, main simulation with two
compute Workers, and worker simulation with two compute Workers; final digest
matches the pre-change CLI. Actual Worker traces show cache hits and executor
phase timings. Native integration tests also compare every tick across execution
backends, and exercise fresh globals, upvalues, current error path, expression
syntax, cancellation and bounded caching.

Keep the bounded compilation cache: repeated nontrivial programs benefit.
Defer VM reuse: it requires stronger reset/isolation work for retained globals,
library state, closures, interrupts and memory exhaustion. Do not trade the
current fresh-VM contract for an unmeasured reset implementation. VM/copy costs
remain visible for subsequent targeted work. No mobile or rendering claim.
