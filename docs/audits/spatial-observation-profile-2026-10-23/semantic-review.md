## Useful cost attribution and its limits

The blind CPU example compares 3 bodies × 4 queries with 4,096 × 256. Its complete post-strict output and counter deltas support 12 and 1,048,576 pair-test upper bounds, 3 and 256 returned hits, and equivalent USB1 body payloads of 128 and 163,848 bytes. Its reported CPU execute samples are approximately 0.0024 and 1.3055 ms, with separately exposed snapshot/input-validation/result-validation/storage phases. Those are individual host-wall samples, not stable benchmark results; independently rerunning the fixture produces different timings.

The informed public and fresh WASM CPU/WebGPU main/Worker workload is separately 4,096 × 128. The actual native GPU Luau integration is a cold 2-body/4-query case on an NVIDIA GeForce RTX 5080 Vulkan adapter. The direct WebGPU regression provides additional geometry/capacity and host-profile evidence. These cases must not be merged into one matched benchmark or represented as blind GPU authoring.

The Web profile's public preparation and queue-wait phases make intake/snapshot and scheduling costs observable in addition to packing, upload, encode/submit, readback wait and decode. For example, the retained Web main GPU sample reports about 18.6 ms total and 9.6 ms preparation, with 4.3 ms validation nested within preparation. Treating that validation as an extra independent phase would overcount. Transport bytes describe the actual GPU transport buffers; `input_body_bytes` is equivalent USB1 size, not all allocation/copy traffic. Pair tests are a body×query upper bound, not measured candidate visits.

All execution phases are host-monotonic wall timings. GPU kernel time is unavailable with an explicit reason; host encode/submit and readback wait are not kernel duration. Missing/inapplicable phases are absent/nil in Luau or null in raw host JSON, rather than fabricated numeric zero measurements. CPU zero GPU transport reflects no GPU traffic. Manager/executor timings exclude the documented Luau/bridge/caller work and per-device/pipeline setup. The samples locate useful bounded costs while leaving those exclusions visible.

Profile reads are detached from canonical spatial state, geometry results and ordinary `info()`. The actually rerun public control/read-only-profile runs have equal nonempty observation digests. Native integration separately checks read purity. Publishing wall diagnostics intentionally makes that observation nondeterministic; equality of diagnostic-publication runs is neither required nor claimed. No GPU speedup, automatic crossover choice, rendered appearance, physical frame-rate gain or other-device result follows from this evidence.
