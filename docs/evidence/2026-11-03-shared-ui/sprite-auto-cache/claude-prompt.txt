1: # Official Web sprite texture cache
2: 
3: This reusable renderer policy controls registered world asset-texture GPU
4: owners, including legacy texture records and the sprite resource pool. They
5: share one controller and one byte/count policy. It contains no map, chunk,
6: character or game-specific behavior. The decoded-image broker, UI image
7: presentation, data textures and render targets have separate ownership scopes.
8: 
9: Declare an optional policy in `player.presentation.json`:
10: 
11: ```json
12: "texture_cache": {
13:   "max_bytes": 67108864,
14:   "max_entries": 128,
15:   "idle_frames": 1800
16: }
17: ```
18: 
19: All three fields are required positive integers. `max_bytes` is at most 1 GiB,
20: `max_entries` at most 65,536, and `idle_frames` at most 36,000 rendered frames.
21: Unknown fields, null, fractions and invalid ranges fail explicitly. Omission
22: uses the bounded defaults shown above: 64 MiB, 128 entries and 1800 renderer
23: frames. The policy is official Web only;
24: custom renderers and native wgpu reject it instead of silently ignoring it.
25: 
26: Each draw protects current sprite references. Active entity leases and explicit
27: prepared-resource leases pin their textures. Several material/program variants
28: of the same catalog asset and sampling configuration share one physical texture
29: owner in the current epoch; that owner is counted once, rather than once per
30: material. A texture requested by mesh, heightfield or projected geometry remains
31: conservatively protected until the owning renderer clears its shared caches.
32: 
33: An ordinary sprite's ready resource may retain an explicit idle cache owner
34: after it becomes hidden or leaves the current set. Its last ordinary-sprite use
35: starts the idle grace period. Managed preparation or managed entity activity
36: does not create or refresh that permission. A resource used only by managed
37: leases retires immediately when its final owner releases it. Pending or failed
38: preparations are not promoted into ready idle entries.
39: 
40: Idle GPU owners are reclaimed oldest first under the shared byte/count pressure,
41: or when their idle TTL expires even without pressure. Idle material/program
42: entries also have a separate count bound of `min(max_entries, 4096)` and an idle
43: TTL; sharing one atlas does not permit unbounded cached shader variants. This is
44: a metadata/program bound, not a second texture allocation budget.
45: 
46: Retirement disposes the GPU allocation and releases its decoded-image lease.
47: The broker may still retain that decoded image under its own policy. Pending
48: loads carry generation and record identity checks: a completed load for an
49: evicted, reset or disposed record cannot resurrect its old GPU owner. A real
50: cold preparation remains pending; the cache does not manufacture readiness or
51: replace the previous complete appearance with a partial texture/UV/uniform tuple.
52: Visible textures are never evicted to satisfy a budget. If the active set alone
53: exceeds the limits, metrics report pressure; the renderer does not introduce
54: missing sprites or claim the limits are a hard memory cap.
55: 
56: The sprite pool also retains its existing hard admission check for active,
57: incoming and reserved unique textures. The official player currently takes
58: those byte/count limits from the image preload plan's budget, independently of
59: the idle `texture_cache` policy. Before rejecting admission, the pool can reclaim
60: its eligible idle owners through the same controller. It cannot evict live
61: owners, bypass admission, or raise the authored limits. This is not another idle
62: texture cache; the CPU decoded-image broker's residency accounting is separate.
63: 
64: Context loss retires idle cache owners and invalidates GPU readiness. Active
65: owners retain the CPU image leases needed for restoration into the new epoch.
66: Reset and disposal retire all registered owners once and fence late completions.
67: 
68: `renderer.metrics().texture_cache` reports entries, loading, releases, estimated
69: decoded texture byte estimates, protected bytes, the effective default/authored
70: policy, and unresolved budget pressure. Estimates count RGBA pixels and mipmaps
71: for the registered GPU owners, excluding driver overhead, encoded files, browser
72: decode copies, UI/data textures, render targets and non-texture resources. A
73: field named `decoded_texture_bytes_estimate` here describes this texture
74: estimate; the image broker's decoded-image residency is a separate report.
75: Neither is a process RSS or total GPU memory measurement.
76: 
77: Games should still share atlases and retire unused entities. This policy is a
78: resource lifetime primitive, not a world streaming or navigation service.

1: # Prepared sprite resources and atomic appearance
2: 
3: `api.sprite` separates resource preparation from publishing an entity's appearance.
4: The project owns animation, pooling, prefetch choices and cache policy. The engine
5: owns decoded images, textures, shader preparation, reference lifetimes and host
6: feedback. No GPU object or writable image buffer is exposed to Luau.
7: 
8: Use the generated `SpriteApi`, `SpriteResource` and `SpriteAppearance` types in
9: [engine.d.luau](engine.d.luau). A resource is an opaque runtime userdata; a table
10: containing its diagnostic `id` is not a resource. Resources cannot be saved.
11: 
12: ```luau
13: local resource = api.sprite.prepare("texture://hero", "hero-tint")
14: -- Retain the resource; preparation is asynchronous.
15: if api.sprite.status(resource).state == "ready" then
16:     local revision = api.sprite.commit(entity, resource, {
17:         transform = {position = {x = 0, y = 0}, rotation = 0, scale = {x = 1, y = 1}},
18:         size = {x = 2, y = 2},
19:         sheet = {columns = 4, rows = 2},
20:         frame = 3,
21:         uniforms = {tint = {1, 0.5, 0.25, 1}},
22:     })
23: end
24: ```
25: 
26: `prepare(assetId, materialId?)` captures the declared image and optional shader
27: material definition. `status` returns `state`, `epoch`, `bytes` and optional
28: `error`. States are `loading`, `ready`, `error` and `released`. Readiness means
29: the selected host prepared its image/texture and shader program for its current
30: epoch. Native currently rejects custom sprite shaders with
31: `SHADER_BACKEND_UNSUPPORTED`; it must not report a fallback as ready.
32: 
33: `commit` returns nil while the resource is not ready. A successful call validates
34: the entire appearance before changing the World, publishes texture, UV/frame,
35: instance uniforms and initial placement together, and returns a revision. An
36: unchanged appearance keeps its revision. Missing `materialId` selects the ordinary
37: sprite material. Per-instance uniforms do not change the declared material's
38: defaults or another instance's mutable uniform storage.
39: 
40: An accepted revision is not a pixel receipt. `getCommit(entity)` returns
41: `requestedRevision`, optional `submittedRevision`, `state`, `epoch` and optional
42: `error`. States are `none`, `pending`, `submitted` and `error`. The official
43: renderer reports submission after a completed frame; this does not certify OS
44: scanout. A context loss changes the resource epoch and invalidates old readiness
45: and submission. Wait for readiness and the first submitted revision after a new
46: resource or recovery. Ordinary ready-page animation need not wait one extra host
47: round trip for every frame.
48: 
49: The renderer retains the preceding complete appearance while a replacement is
50: pending. It never mixes a new texture with old UVs or old instance uniforms.
51: Live transform/physics movement after a commit retains the resource and revision.
52: Legacy sprite/frame/material replacement, despawn and `setSpriteVisible(false)`
53: invalidate the managed appearance, so a late preparation cannot resurrect it.
54: An explicit hidden appearance can acknowledge absence after a successful frame;
55: a globally suppressed visible sprite cannot claim submission.
56: 
57: `release(resource)` is idempotent and relinquishes that handle's caller lease.
58: Entities that committed it retain their own ownership until hidden or replaced.
59: Several entities may share one handle. Several Luau aliases of that same handle
60: share one caller lease; call `prepare` separately for independent caller release.
61: The Web host shares physical image/texture storage across material preparations
62: for the same catalog asset and sampling settings. Program readiness remains
63: specific to its shader and render-target variants.
64: 
65: Ordinary sprite presentation can retain a ready resource through an explicit
66: renderer-owned idle cache lease. This is separate from caller and committed
67: entity leases. A managed-only resource still retires on its final release;
68: managed use does not grant or refresh ordinary-sprite idle retention. Pending
69: loads and failed preparation do not become ready cache entries. The renderer
70: continues to hold the preceding complete appearance while a true cold resource
71: is pending.
72: 
73: One registered GPU texture-cache controller covers legacy world texture records
74: and sprite-pool owners. Its omitted policy is 64 MiB / 128 entries / 1800 renderer
75: frames, configurable through `texture_cache` in `player.presentation.json`.
76: Shared material variants count a physical asset/sampler/catalog/epoch texture
77: owner once. Idle material/program entries are separately bounded by
78: `min(texture_cache.max_entries, 4096)` and their idle TTL. Context loss retires
79: idle cache owners while active CPU image leases remain available for restoration;
80: old-epoch completions cannot restore retired resources. See the
81: [texture-cache contract](texture-cache.md) for eviction and pressure semantics.
82: 
83: Host resource plans and scalar receipts travel outside the canonical World.
84: `presentation_resources` is recorded input, containing resource and appearance
85: receipts. Manual/replay input stays authoritative. Failed ticks retain admitted
86: feedback and roll back the appearance transaction. GPU/image objects never cross
87: the worker boundary. Reload/session/context epochs fence late completions.
88: 
89: Generic safety limits are 4096 live resource handles/owners, at most 256 resource
90: and 256 appearance receipts per input batch, exact positive safe-integer epochs
91: and revisions, and at most 1 GiB reported bytes per resource. The sprite pool's
92: existing hard admission limit still covers active, incoming and reserved unique
93: textures, including outgoing owners retained during a transition. The official
94: player currently takes these byte/count limits from the authored image preload
95: plan budget (default 64 MiB / 128 entries). This check remains distinct from the
96: single idle `texture_cache` policy. Admission can reclaim eligible pool idle
97: owners through that controller before reporting a budget error; it cannot evict
98: live owners, bypass the limit or increase the authored budget. A larger generic
99: safety limit is not a memory budget. Decoded-image broker residency, other
100: renderer allocations, render targets and browser copies have separately reported
101: scopes; none of these estimates is total process memory or VRAM.
102: 
103: See [immutable byte views](decisions/0049-bounded-immutable-byte-views.md) for
104: binary buffer ownership. Sprite resources do not expose a writable buffer alias.
